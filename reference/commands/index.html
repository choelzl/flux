    Commands and placeholders¶

    How every command a document names runs, the placeholders it gets, and its contract: arguments, output, exit code.

    How commands run¶

    Checks, stages, estimates, the generator, the search, the baseline and the composition all run the same way, written run: (command: is refused). Your own agent differs: agent command.

    • Form: a list of arguments, or a string split like a shell would, but no shell runs. For pipes: ["sh", "-c", "cat {artifact} | wc -l"].
    • fluxpreset first runs a preset (fluxpreset rtl measure ...). From a script of your own, a preset is "$PY" -m flux_presets NAME ... with {python} passed to the script: fluxpreset need not be on its PATH.
    • vscode task NAME or vscode launch NAME first runs your project's VS Code task or launch configuration.
    • Working directory: for a loop of your project (a .flux folder), its checks and stages -- a stage's read too, and an agent's probe of either -- run in the project, {project} (the tool slot's copy with workspaces: per-slot): make, sh sim.sh, a relative path all mean your project, no cd needed. Every other command of such a loop (the generator, the baseline, the search and its scope, an estimate) and every command of any other loop runs in {workdir}, the pass's folder (a design's own folder under it when designs run at once). Write scratch to {workdir}/, never relatively into the project: in the sandbox the project is read-only unless the loop has workspaces, and a step that writes there fails and is told so. Use {home}/... for the loop's files, {project}/... for your project's from anywhere.
    • Environment: Flux's, with MAKEFLAGS cleared, FLUX_JOBS set (make -j"$FLUX_JOBS", verilator --build-jobs "$FLUX_JOBS"), ccache's variables, FLUX_PROJECT -- what {project} is for that command, so a script of yours need not be handed it (cd "$FLUX_PROJECT") -- and for one design's checks and stages FLUX_REUSE_DIR (Compiling). Set for every step Flux runs, never inherited by a tool a step starts through Flux.
    • stdin: not data; do not read it.
    • Output: stdout and stderr captured separately; checks and stages read both. Live shows the command, folder, output and exit.
    • Timeouts stop the whole process group. A missing program is "not found on PATH"; Check lists them.
    • Placeholders are replaced in every argument, unquoted. An unknown {name} is refused at load (not checked inside arguments with spaces, such as sh -c scripts). A placeholder with no value for that command is left as written.

    Command placeholders¶

    Placeholder Value Generator Check, stage, estimate Search Baseline Composition
    {artifact} Path of the design file (<workdir>/<name><ext>) writes it reads it "" writes it writes the whole
    {home} The document's folder (absolute) ✓ ✓ ✓ ✓ ✓
    {project} The folder a .flux loop lies in; for any other loop, {home}; with workspaces: per-slot, the step's tool slot's copy. Also the step's FLUX_PROJECT ✓ ✓ ✓ ✓ ✓
    {workdir} The pass's working folder (a design's own under it when designs run at once): the place for scratch ✓ ✓ ✓ ✓ the compose folder
    {python} The interpreter running Flux ✓ ✓ ✓ ✓ ✓
    {name} The design's name (mul8#3, slice_sieve) ✓ ✓ search ✓ the loop's id
    {vars} Path of a JSON file of vars ✓ ✓ ✓ ✓ ✓
    {knob} One knob's value (True/False for booleans) search mode ✓ first choices
    {point} Path of a JSON file of every knob search mode ✓ "" ✓ ""
    {failure} Why the last attempt was refused (text) drafting ""
    {attempt} 1, 2, ... drafting 1
    {history}, {state} Search history and the search's own state file ✓
    {metrics} The stage's declared metrics:, comma-separated, in the document's order; Check asks the preset whether its stage can give them stage only
    {scope} The scope a pass works on, in search.scope's brief and check
    {prompt}, {prompt_file}, {session}, {answer} Brief and session, for your own agent

    {part} is refused (a loop is one design).

    File formats:

    • {vars}: vars.json in {workdir}, the document's vars.
    • {point}: <artifact>.point.json, components nested ({"algorithm": "list_sieve", "prefetch": {"distance": 2}}); an optional component that is off is left out.
    • {failure}: text, not a file: the last 4000 characters of the failing check's output (failed at <check>: with several checks), or a send-back reason. Empty at first.

    VS Code tasks and launch configurations¶

    A check, a stage or any other command can run a task of your project's .vscode/tasks.json or a configuration of its .vscode/launch.json, by its label or name. A name with spaces is quoted ("Run tests" or 'Run tests'). Anything after the name is added to the task's arguments:

    flow:
  check:
    build: vscode task build
    test: vscode task "Run tests" {artifact}
  measure:
    bench: {run: vscode launch Bench {artifact}, metrics: [time_ms]}
    • Read at each run: an edit of the task is what its next run runs. Check shows each step's command as it would run, and refuses a missing file, task or configuration. A name cut at its first space (vscode task Run tests) is told the quoted one it may mean.
    • Results stay honest: the command as resolved (its folder and environment too) and the .vscode file are part of what a measurement was made from, so editing the task makes the earlier measurements stale, as editing a script does.
    • Tasks: shell and process tasks (no type: a process), with command, args and their quoting, options.cwd, options.env, options.shell (a shell task runs in bash otherwise) and the linux overrides. dependsOn tasks run first, in order. problemMatcher, presentation and group are ignored. Tasks of an extension (npm, cmake, ...) and background tasks are refused.
    • Launch configurations (request: launch) run their program: python/debugpy (python program args, or -m module; the configuration's python, else python3), node/pwa-node (runtimeExecutable, runtimeArgs), cppdbg, cppvsdbg, lldb and gdb (program args), with cwd and env. A preLaunchTask runs first. envFile is refused.
    • Variables: ${workspaceFolder} and ${cwd} are {project}, ${workspaceFolderBasename} its name; the older ${workspaceRoot} and ${workspaceRootFolderName} mean the same, and ${workspaceFolder:NAME} works when NAME is the project folder's own name. ${userHome}, ${env:NAME}, ${pathSeparator} and ${/} work. ${config:NAME} reads the setting from the project's .vscode/settings.json (your user settings are not seen, so a setting must be there). ${defaultBuildTask} is your default build task, so "preLaunchTask": "${defaultBuildTask}" works. Variables only the editor knows (${file}, ${selectedText}, ${command:...}, ${execPath}) are refused, and the message lists the ones that work.
    • Inputs: ${input:ID} reads the inputs of the same file (a launch configuration's from launch.json, a task's and a preLaunchTask's from tasks.json). The step answers it with --input ID=VALUE right after the name, else the input's default is used; with neither the step is refused and told how to set it. A pickString takes one of its options' values; a promptString any text. {artifact} and the other placeholders work in VALUE. A password input runs with its value but Check and the graph show ${input:ID}, and changing it does not make results stale. command inputs are refused: only their extension can answer them.
    build_ut: vscode task "Build UT" --input target=ut_core {artifact}

    Arguments come after the inputs; put -- before arguments that start with --input. - Running: like any command, in the same sandbox, folder rules and timeout. A task's default folder is the project, not {workdir}: pass the design with {artifact}.

    Command contracts¶

    Generator command¶

    design: {run: ...} writes one design to {artifact}. Its stdout is not the design.

    • Drafting (no space): a refused draft reruns with {failure} and {attempt}, up to budget.repairs_per_design times. A failing command (non-zero exit, or no file) or the same design twice ends the repairs.
    • Search (a space): once per point, with its {knob}s and {point}. A failure drops the point; no repair. The design is named after its knobs.
    # document: design: {run: "{python} {home}/gen.py {artifact} {attempt} {failure}"}
import sys
out, attempt, failure = sys.argv[1], int(sys.argv[2]), sys.argv[3]   # failure is "" at first
design = "def count_primes(n):\n    ...\n" if not failure else "...a design that fixes it..."
open(out, "w").write(design)                                         # exit 0

    Check command¶

    A check reads {artifact} and reports failures. Flux reads stdout and stderr together:

    1. Exit 3 means the design did not build, whatever was printed. For a check named build, any non-zero exit means that.
    2. Otherwise, with count_re (default (\d+) failing): the first match's number is the failure count. With fail_re only: each match is one failure.

    3. With no match: exit 0 passes, any other exit is one failure.

    4. A printed count wins over the exit: 2 failing with exit 0 fails; 0 failing with exit 1 passes.

    5. The first check with failures refuses the design; its last 4000 characters go to Live and back to the model or agent.
    6. stderr debug output fails nothing unless a pattern matches it.
    # document: check: {correctness: "{python} {home}/check.py {artifact}"}
import importlib.util, sys
try:
    spec = importlib.util.spec_from_file_location("design", sys.argv[1])
    design = importlib.util.module_from_spec(spec); spec.loader.exec_module(design)
except Exception as exc:
    print(f"did not load: {exc}"); sys.exit(3)                 # 3: did not build
cases = {10: 4, 100: 25, 1000: 168}
bad = [n for n, want in cases.items() if design.count_primes(n) != want]
for n in bad:
    print(f"FAIL n={n}: got {design.count_primes(n)}, expected {cases[n]}")
print(f"{len(bad)} failing of {len(cases)}")
sys.exit(1 if bad else 0)

    Measurement command¶

    A stage reads {artifact} and prints its numbers. It must exit 0; on any other exit its numbers are discarded and the design is refused at that stage. Flux reads stdout and stderr:

    • name=value, at the start of a line or after a space: the first occurrence of each metric counts. value is a number (1.5, -2e3); nan and inf are unmeasured.
    • A JSON object on a line of its own (it may span lines): its keys that are declared metrics are read. A name=value line overrides it.
    • A dictionary metric: name={"test": 12, "other": null} (the last occurrence counts), or a dictionary in the JSON object. Each finite entry is name.test; name is the objective's aggregate, else its _a (gate_count={"AND": 41, "OR": 34, "_a": "sum"}: mean, median, min, max or sum), else the mean. If designs disagree on _a, the first one met wins (the journal says so). An unranked dictionary is recorded and shown only.
    • A dictionary a test a line: name.test=12 (the test is everything up to the =, dots included: cycle.DL_UT.crs_para_2t=108503) is the same dictionary as name={"test": 12}. A test's last line counts; name._a=sum is its _a. A metric also printed whole (name=, or in the JSON object) is read whole, its dotted lines ignored.

    • metrics_re, if given, replaces the name=value patterns: one capture group each.

    • Exit 0 with no metric refuses the design ("no metric matched in the output"). Some metrics: recorded with those.

    • read: a stage that says it runs it after its command exits 0 (same folder, environment and timeout_s, what is left of it), and reads its numbers from the read's output alone, by the rules above. It must exit 0 too ("its read exited 1: ..."); a failed command is never read.
    • For timings set budget.tools_at_once: 1 (one slot pool for checks, measurements, probes).
    # document: measure: {bench: {run: "{python} {home}/bench.py {artifact}", metrics: [time_ms]}}
import importlib.util, statistics, sys, time
spec = importlib.util.spec_from_file_location("design", sys.argv[1])
design = importlib.util.module_from_spec(spec); spec.loader.exec_module(design)
runs = []
for _ in range(5):
    t = time.perf_counter(); design.count_primes(1_000_000); runs.append((time.perf_counter() - t) * 1e3)
print(f"time_ms={statistics.median(runs):.3f} time_spread_ms={max(runs) - min(runs):.3f}")

    The measurement cache: a stage does not measure a design again while nothing it depends on changes: the design's text (or knobs), the stage's command, metrics and patterns, vars, the knobs it names, the folder's files (except out/, runs/, workbench/, library/, the documents), the {home}/... files it names, and its programs' and needs' builds. Only successes are reused. The cache is the record: a new record starts empty.

    Estimate command¶

    estimate: {kind: command, run: ..., margin: 0.1} runs before the stage for each uncached design, with the stage's placeholders and timeout, printing the stage's metrics. A non-zero exit or no numbers: the tool runs. Missing a cutoff or limit by more than margin (a fraction of the limit): skipped, recorded as refused by the estimate.

    # document: estimate: {kind: command, run: "{python} {home}/estimate.py {artifact}"}
import sys
print(f"time_ms={len(open(sys.argv[1]).read()) * 0.01:.3f}")

    Search command¶

    search: {run: ..., timeout_s: 600} is your own search. Each round, Flux writes {history} and runs the command; the command answers with JSON on stdout.

    {history} (search-history.json in {workdir}):

    {"measured": [{"name": "w4", "knobs": {"w": 4}, "stage": "bench", "metrics": {"time_ms": 3.1}, "by": "mine"}],
 "refused":  [{"name": "w9", "why": "failed at correctness: 2 failing"}],
 "guidance": "operator notes, if any",
 "round": 3}

    {state} (out/<record>.search-state.json) is yours: read it if it exists, write it every round; it survives restarts.

    The answer is the last line of stdout that is a JSON object (or the whole stdout):

    Key Meaning
    candidates [{name, artifact, knobs, why, by}]: name required; artifact is the design's text (not a path); knobs reach the checks and stages as {knob}/{point}
    lessons Lines added to the run's lessons
    not_established Lines added to the report
    conclusion What the search concluded, recorded when nothing is decided
    say A line printed with the round
    done true: this is the last batch

    No candidates ends the search, as does a non-zero exit or no JSON (with a note). Candidates go straight to the checks; the generator does not run.

    # document: search: {run: "{python} {home}/search.py {history} {state}", timeout_s: 300}
import json, os, sys
history, state_path = json.load(open(sys.argv[1])), sys.argv[2]
state = json.load(open(state_path)) if os.path.exists(state_path) else {"next": 1}
tried = {m["name"] for m in history["measured"]} | {r["name"] for r in history["refused"]}
cands = [{"name": f"w{w}", "artifact": f"WIDTH = {w}\n", "knobs": {"w": w}, "why": "next width"}
         for w in (state["next"], state["next"] + 1) if f"w{w}" not in tried]
state["next"] += 2
os.makedirs(os.path.dirname(state_path), exist_ok=True)
json.dump(state, open(state_path, "w"))
print(json.dumps({"candidates": cands, "done": state["next"] > 8}))

    Baseline command¶

    baseline: {run: ...} runs once before pass 1, with the first point (first choices, overlaid by the first seed). It writes the reference to {artifact}, or prepares the project and writes nothing (checks and stages then use {home}/...). A non-zero exit records "baseline failed"; the loop goes on.

    Agent command¶

    Your own coding agent: by: {run: [my-agent, "--prompt", "{prompt_file}"], output: text, resume: [...]}. Write run as a list.

    • Placeholders use Python formatting: {prompt} (the brief; very long briefs become an instruction to read the file), {prompt_file}, {artifact}, {workdir} (the session folder), {name}, {python}, {home}, {workbench}, {probe}; a resume command also gets {session} and {answer}. Write a literal brace as {{ or }}; an unknown name refuses the draft.
    • The brief goes to stdin unless the command names {prompt}, {prompt_file} or {answer}.
    • It runs in its session folder with Flux's environment, plus FLUX_<NAME>_ENV and FLUX_PROBE. Default timeout 1800 s.
    • It writes {artifact}. If it does not, its reply is read: a JSON artifact field, else the largest fenced code block.
