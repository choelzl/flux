    Glossary¶

    The words Flux and its web app use, one term each.

    Loop. A folder holding a document, problem.yaml, and the scripts and files it names. The folder's name is the loop's id. Flux generates designs, checks and measures them, and decides, pass after pass.

    Document. The loop's problem.yaml: what to make (statement, contract), who does each box (flow), what wins (objectives) and how much to spend (budget). See the Document reference.

    Start. One launch of a loop, from Start (or flux task run) until it stops. A loop keeps one log and one record across its starts; each start resumes from the record.

    Pass. One trip round the loop: choose what to try, make a design, check it, measure it, decide. budget.passes or --passes N caps them; without a cap a run goes on until stopped.

    Box. One step of the loop as the configurator's Graph draws it, nine in all. Setup, before the passes: Plan (plan), Knowledge (knowledge) and Notes (feedback). Each pass: Search (orchestrate), Design (generate), Check (test), Measure (measure, its calibration too) and Choose (select). Then Record, always on. flow says who works each box.

    Check. A command that decides whether a design is correct (flow.test). Checks run in the order written; the first that reports failures refuses the design. Together they are the gate: a design that fails it is never measured.

    Measurement. A command that puts numbers on a design that passed the gate. Each measurement is a stage of flow.measure; stages run cheapest first, and a cutoff decides which designs go on to the next.

    Design. One candidate the loop made: a file (the artifact) written by a script, a model or an agent, with its checks and measurements on the record.

    Design name. Each pass's design takes the next number, a new draft or an edit of the standing design alike: pass 1 primes#1, pass 2 primes#2 (from primes#1), pass 3 primes#3 (from primes#1). The numbers go on after a stop and a restart. Inside a pass, the tries are primes#3, primes#3.2, primes#3.3 ...; the try the gate passes is the pass's design and is named primes#3. A refused try goes on the record under its own text (primes#3~1a2b3c). A pass none of whose tries passed spends its number, so the record can have gaps. Two designs whose texts differ only in spacing, or in comments (Python, Verilog, SystemVerilog, C, C++), are the same design: a draft that repeats a measured one is refused before it is built ("the same as primes#1"). A search's points (arch=ripple) and a composition of parts keep names of their own.

    Standing design. The design the next pass builds on: the last decision on the record (with nothing that meets every limit, the closest). A run started again keeps it.

    Decision. The design that meets every limit and is best on the objectives. Flux writes it under out/. When none meets every limit, the closest is reported, not decided. "Then earliest" after its Decided by means another accepted design ties it on every objective: the one made first (measured first) is the decision.

    Record. The SQLite file a loop writes, out/<id>.db: every design, check, measurement and refusal, with where it came from. A rerun reuses it.

    Campaign. The command line's word for one line of work inside a record, named after the loop. --campaign on flux report, flux stop and the others picks one; by default, the latest.

    Objective, limit, preference. An objective is a metric and a direction. With a goal it is a limit (at least or at most a value); without one it is a preference, compared in the order written.

    Front, knee. The front (Pareto frontier) is the set of designs no other design beats on every objective at once. The knee is where improving one objective starts to cost much more of another.

    Knob, space. A knob is one setting with a list of choices; the space is all of them (flow.orchestrate.space). A point is one choice for every knob.

    Search. How the next points are chosen (flow.orchestrate.search): sweep, montecarlo, gradient, anneal, genetic, pareto, phases, or FluxAgent or an agent proposing them (by: flux beside the space). See Searches.

    Policy. The intent that guides who decides, the points FluxAgent proposes, or a search's prompts (flow.orchestrate.policy): adaptive, explore, improve, tune, finetune, variations.

    Part, sub-loop. A part is a piece of one design, written and checked on its own (parts). A sub-loop is a child loop in its own folder (subtasks), whose decided designs a parent can compose. See Split a larger design.

    FluxAgent. Flux's own language model, on an OpenAI-compatible endpoint, as a worker: flux in a document (generate: flux, {by: flux}), a chat or --author; model, its old name, is the same. It can propose points, write designs, review the document, digest papers and answer in Chat.

    Agent. A coding agent (Claude Code, Codex, OpenCode, or one a server adds) that takes a brief and writes files. It runs on its own model settings, never on Flux's. See Models and agents.

    Critic. A second opinion on a box: Search (the split), Check (each design its checks passed), Measure (a stage's numbers) or Choose (the pick), each set in its box's panel in the configurator's Graph. Its rejection is a verdict: the work is divided again, the design fails, the numbers are marked, or the pick is made again. See critics.

    Author. In flux ask and New loop › Agent, FluxAgent or an agent that writes the document and its files from your prompt.

    Knowledge, library. What the model and agents can look up besides the document: the loop's library (library/, the files flow.knowledge.library lists, the projects'), read on demand with flux knowledge and never pasted into a prompt, and the insights drawn from the record (flux knowledge insights, never pasted into an agent's brief).

    Ideas notebook. The hypotheses the loop's model and agents proposed, each with the designs that tested it, kept across passes (Results › Ideas). The ideas cleanup merges repeated ideas into one; a merged idea is kept, folded under the one it was merged into. Each idea has a number, said "idea 3" (oldest first), so it is never taken for design #3.

    Skill. A folder with a SKILL.md (a name, a description, then instructions) that the model and agents can load. The loop's skills/ folder is read by default.

    Workbench. The agents' own folder beside the document, workbench/: tools they build and notes they keep, shared by the loop's agents and kept across runs.

    Chat. A conversation with an agent or FluxAgent that belongs to no loop, in the web app's Chat tab. It may read your loops (read-only) and keep tools and notes in your chat workbench, one folder for all your chats, as the admin allows and you switch on. See Chat.

    Hidden from AI. Paths no agent or prompt may read, such as the gate's tests (knowledge.hidden). The loop's own commands still read them.

    Golden model. A short Python file, usually golden.py, that says what a hardware design must compute (PORTS and golden(**inputs)), not how. See Presets.

    Prototype. The algorithm written first in Python (or SystemC) and checked against the golden model before the hardware design is written.

    Baseline. A reference measured before pass 1 (pass 0), such as the design you have today. Results can be read relative to it; it is never the decision.

    Preset. One of Flux's own checks and measurements, run as fluxpreset NAME. See Presets.

    Archived loop. A stopped loop kept read-only: its record, document, files, workbench, last log, Chat and task journals stay; its pass folders, tool outputs, caches, scratch and older logs are deleted. The loop lists show it under Archived; Unarchive makes it editable again. See Archive.

    Sandbox. The container flux task check, flux task run and flux ask run in, so a loop's code and agents cannot touch the rest of the machine. See Run, stop, resume.

    ULP. A unit in the last place: the gap between two neighbouring floating-point numbers. "Within 1 ULP" means at most one step from the exact result.

    ASAP7. A free, predictive 7 nm process design kit from Arizona State University. Flux's area, timing and power numbers are on ASAP7, not on a commercial process.
