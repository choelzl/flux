    Agent options¶

    The options a coding agent takes in a document. Boxes an agent may work: Document reference. Model and login: Models and agents.

    Options¶

    • Written beside by: <agent> on a box or a critic. Beside by: flux or no by: ignored, with a warning.
    • With a list (design: {by: [claude, {by: codex, model: gpt-5-codex}], timeout_s: 1800}), options beside the list apply to all; an entry's own win (several Design agents). Sessions are each agent's own.
    Option Default Purpose
    model The agent's own (or its settings) Its model by name, as the agent takes it: {by: codex, model: gpt-5-codex}, OpenCode's provider/model; it wins over every setting. Refused beside by: flux and for your own run: (give it in your command). The older args: [--model, …] still works, but not both at once
    provider None The provider a model is isolated to, beside model: ({by: codeagent, model: GLM-V5.1, provider: wireless}), for a build whose CLI takes one with its model: passed as the agent's provider_flag before the model (--provider wireless --model GLM-V5.1). Refused with no model, with no flag known (say provider_flag on the definition) or beside that flag in args (Your own agents)
    provider_flag The kind's own: none for Claude Code, Codex and OpenCode On a definition (agents:): the flag its CLI takes a model's provider by, e.g. --provider. Nothing is added until a provider: is said
    timeout_s 1800 Most seconds for one turn
    session none none: a new session each pass, on design one per design until it is admitted (its repairs go on in it); seed (design only; Claude Code, Codex and OpenCode): each design's session forked from a seed a pass's Setup made, a turn that read the loop first (Sessions); keep: its sessions kept pass after pass, one per design at once, never renewed for their turns. The papers' digest, the workbench and the ideas have none. Older words: pass, fresh and turn are the default (a warning; remove the line), seeded is refused naming seed
    seed_timeout_s 3600 With session: seed: the most seconds the seed's turn may take, 300 to 10800, whatever timeout_s says; refused elsewhere
    every 10 With session: seed: the seed is made again at the Setup after this many passes, 1 to 1000; refused elsewhere (reseed_after_bests, which it replaced, does nothing: a warning)
    questions decide Who answers a question the agent asks (your own run: agent asks by writing question.json in its folder): decide (nobody), flux (FluxAgent; model too), operator. Not on a box whose agent answers in one turn (search, plan, choose, the insights, a critic): nobody answers there, so it is a warning, ignored
    max_questions 2 Question exchanges per draft (as questions)
    wait_s 300 Seconds to wait for the operator's answer (as questions)
    probe {gate: 20, stages: 3} Probes per turn the design agent (design) may run: its current file against the loop's gate, and against its stages; per stage {bench: 2}; false turns them off; elsewhere a warning
    allow [] Tools the agent may run itself, e.g. [yosys], or all
    effort The server's thinking by default: the agent's own unless an admin set one How hard it reasons: Claude Code low, medium, high, xhigh, max; Codex none, minimal, low, medium, high, xhigh (as its model takes them: none and minimal are not every model's); OpenCode minimal, low, medium, high, max (as its provider names them); refused for your own command. It wins over think. FluxAgent takes low, medium, high, max beside by: flux (Effort)
    think The server's thinking by default true: the agent's effort for thinking; false: its effort for not (Admin › Runtime › Agents) -- the box's Thinking switch; refused for your own command
    instructions None Text added at the end of every brief this agent gets, after its kind's Instructions (Admin › Agents); a definition's (agents:) or beside by:; your own run: agent's too (4,000 characters at most, the rest cut and said so)
    hidden [] More paths this agent may not read, beside knowledge.hidden (Hidden from AI)
    hosts [] Hosts this agent reaches beside its endpoint's ([gw.example.com, "*.corp.example"]: a host, *.domain, an IP, a CIDR), allowed to a run of it on a full machine that is lent its login; a definition's (agents:) or beside by:. The admin's and your Allowed hosts for the agent add to it (Account › Agents)
    bin The agent's Program (Admin › Runtime › Agents), else its interface's own: claude, codex, opencode (on a VS Code machine, an agent's VS Code extension's) The program to run. On a definition (agents:) it is enough: the interface Flux drives it with is told by the program's --help (Interface)
    args None Extra arguments, added before the prompt (the model is model:)
    output text Your own agent: how its output is read (text, opencode, claude, codex)
    argv Its kind's A claude, codex or opencode agent: its own arguments for a fresh turn, after its program, in place of its kind's (Command lines)
    resume Its kind's Your own agent: the command that resumes a session ({session}, {answer}); without it session: keep begins a new session every pass (task check says so). A kind's agent: its arguments for a resume, after its program (Command lines)
    fork Its kind's A kind's agent: its arguments for a design's session forked from its seed (session: seed, Sessions) (Command lines)
    name The program's (in agents:, the definition's) Your own agent: its name in the record

    Agents of the document's own¶

    • agents: at the document's top level names agents once: codeagent: {bin: /opt/tools/codeagent}, work-claude: {kind: claude, bin: /opt/tools/claude-wrapper, args: [--profile, work]}, or inhouse: {run: [inhouse-agent, "{prompt_file}", "{artifact}"], output: text}. Every by: that takes an agent may name them (Your own agents).
    • bin alone is enough: the agent is driven with the interface its program speaks. kind (claude, codex or opencode) says it instead -- an override; alone, it runs that interface's own program. run:: a program of your own, its output, resume and name (the definition's name unless said).
    • Every option above may sit in a definition; a box's own win. model, provider, effort and think are a kind agent's; a definition's provider goes with its model (a box saying a model of its own leaves it behind), and provider_flag is the definition's alone to say.
    • bin and run:'s program: a path ({project}, {home}, ~) or a name on PATH, checked where the loop runs -- task check checks it (a box's own bin too) with the document's env:.
    • Its Instructions: its kind's (Admin › Agents), none for run:; then its own instructions:, any kind's or run:'s.

    Interface¶

    An agent is a program and the interface Flux drives it with -- Claude Code's, Codex's or OpenCode's command line: its flags, how its output is read, its sessions, efforts and login files. The interface is told from the program itself: <bin> --help (no model call, no login, a short timeout, an environment of its own) names the flags and subcommands of one of the three, and Flux recognises them. The answer is kept per program as it is on disk (its path, target and file identity): an upgrade is asked again. kind: is an override; where neither tells -- --help names no known interface -- the document is refused where it is read ("agents.X: ... --help names no known interface (claude, codex, opencode); kind: claude|codex|opencode says it") and flux agent test NAME --loop fails its interface step, in a few words. A program that is not on the machine reading the document has its interface told where it runs (the loop runs its agent where the program is); that machine reads the definition as Claude Code's, with a warning, until it runs. A server's added agents (Admin › Agents) are told the same way; there and in VS Code the override is Interface under Fine-tune, its Default what the program says. The agent is shown everywhere by its own name and its program's version, never by the interface's name.

    Command lines¶

    A kind agent runs its kind's command lines. A build of that CLI that takes other flags (a company's fork, a wrapper) may give its own: argv (a fresh turn), resume and fork, each the arguments after its program (bin). Everything else of its kind stays: how its output is read, its sessions, its Instructions, what it may not read or run (Claude Code's deny list follows each line), its test and login. args, model and effort are still added to each line: at its end, or before a last {prompt} that stands alone.

    agents:
  codeagent:
    kind: opencode
    bin: ~/.local/bin/codeagent
    argv: [run, --format, json, --dir, "{workdir}"]   # OpenCode's, without --thinking
    • An unsaid resume or fork that begins with its kind's argv (OpenCode's) begins with yours; otherwise it stays its kind's, with a warning.
    • Placeholders: {workdir}, {prompt}, {prompt_file}, {artifact}, {name}, {python}, {workbench}, {home}, {project}; a resume also {session} (needed) and {answer}; a fork its kind's ({seed}, OpenCode's {forked}, needed). Any other is refused when the document is read; leaving out one its kind's line names ({workdir}) is a warning.
    • The brief goes on stdin unless a line names {prompt} or {prompt_file}. In a resume they carry its message (an answer, a repair, a nudge), as {answer} does.
    • Checked where it is said: in agents: or on a box (an entry of Design's list too).
    • flux agent test NAME --loop PATH prints the lines a turn runs (argv:, resume:, fork:), with its program, args and effort.

    Each kind's own, after its program (flux agent test claude prints them with Claude Code's deny list, --allowedTools Bash --disallowedTools AskUserQuestion Bash(verilator:*) …, after each):

    Kind argv resume fork
    claude -p --permission-mode acceptEdits --output-format stream-json --verbose --include-partial-messages -p --resume {session} then argv after its -p -p --resume {seed} --fork-session then argv after its -p
    codex exec --json --sandbox workspace-write --skip-git-repo-check -c features.apps=false -c features.plugins=false -c features.in_app_browser=false - exec resume {session} --json --skip-git-repo-check -c sandbox_mode="workspace-write" and the same -cs, - exec fork {seed} then as resume
    opencode run --format json --thinking --dir {workdir} argv then --session {session} argv then --session {forked}

    Flux never asks Claude Code to skip its permissions, on any turn: no --dangerously-skip-permissions, no bypassPermissions mode, and its --settings holds the hidden paths' permissions.deny alone. When an agent exits before its output begins, its failure ends with Flux ran: <the command line> and where each part came from: the program (its bin, FLUX_<NAME>_BIN, FLUX_<KIND>_BIN, PATH), its lines, args (the document's, or the agent's Extra arguments, FLUX_<NAME>_ARGS), model and effort. A refusal such as "--dangerously-skip-permissions cannot be used with root/sudo privileges" with no such word in that line comes from the program's own settings: its settings files (permissions.defaultMode), its environment, or a wrapper at bin.

    What an agent may run¶

    • By default an agent runs no compilers, simulators or test runners itself: it probes its file against the loop's gate and stages.
    • allow gives tools back ([yosys], or all). probe: false turns probes off.
    • Probes wait for a budget.tools_at_once slot like the loop's own runs.
    • Your own agent: by: {run: [my-agent, "{prompt_file}", "{artifact}"]} (agent contract).
