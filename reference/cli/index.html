    CLI¶

    Every flux command's own help, as flux COMMAND --help prints it. The checks and measurements Flux ships are a separate command, fluxpreset (see Presets).

    flux¶

    usage: flux [-h]
            {new,ask,consult,chat,task,loop,probe,tools,prog,report,log,run,status,stop,attach,serve,user,login,agent,selftest} ...

Flux: an AI-driven design-space exploration loop. A model or a coding agent proposes designs, real tools check and measure them, the loop decides and keeps a record.

options:
  -h, --help            show this help message and exit

commands:
  {new,ask,consult,chat,task,loop,probe,tools,prog,report,log,run,status,stop,attach,serve,user,login,agent,selftest}
    log                 Every model and coding-agent turn of a campaign's
                        runs: prompts, replies, tool calls, errors.
    probe               Inside an agent's turn: check a file with the loop's
                        own gate or stage.
    loop                What a loop already knows, read back: its summary,
                        passes, ideas, designs tried, results, designs
                        compared, events, a design, the designs nearest a
                        file, papers; its gate on a file.
    knowledge           A loop's library, its insights and its projects'
                        accepted knowledge: list, search, show, insights.
    library             A loop's library read in pieces: list, search, digest,
                        outline, read.
    workbench           The loop's workbench searched: find the tools and
                        notes a need names, the note on a subject.
    serve               The web interface: accounts, loops, runs followed
                        live.
    user                The web interface's accounts, from the server's
                        machine.
    project             The web interface's projects (a group's, or global),
                        from the server's machine.
    web-loop            The web interface's loops, from the server's machine:
                        list, start, stop, status.
    web-agent           The web interface's users' agents, from the server's
                        machine: their gate, their Test.
    web-move            A server's data copied from another folder says its
                        own folders anew.
    selftest            Check this machine: a command-driven loop, the model,
                        optional application tools.
    new                 Write a loop's baseline to fill in: the skeleton
                        problem.yaml, a README of the folder's parts,
                        library/.
    consult             A question about a loop, answered by an agent that
                        reads it and changes nothing.
    chat                A message in the web's Chat, answered by an agent
                        bound to no loop: the user's loops read-only, their
                        workbench writable.
    login               A coding agent's login, its home a given folder (an
                        external user's agents in the web).
    agent               Coding agents: is one ready for you.
    ask                 The loop from a prompt and files: an author writes the
                        problem, the loop runs it, the author steers.
    task                Check or run a problem document through the loop.
    report              How a campaign moved: frontier evolution, hypervolume,
                        best-so-far, the parts.
    run                 Start a command detached, its log under the trace
                        root.
    status              Is the campaign running, since when, how many passes.
    stop                Stop the campaign's run at the pass boundary (or
                        --now).
    tools               The checks a gate may run and the stages a document
                        may measure with.
    attach              Tail the log of the campaign's run (started by `flux
                        run`).

start with:
  flux new myloop            (the baseline to fill in)
  flux task check <folder>
  flux task run <folder>
  flux ask "what you want" --file spec.pdf
docs: https://choelzl.github.io/flux/

    flux loop¶

    usage: flux loop [-h]
                 {summary,passes,notes,show,ideas,tried,results,compare,events,design,diff,similar,library,digest,gate,measure} ...

Reads a loop's record and library. Inside an agent's turn it reads that turn's
loop; elsewhere --loop (a folder, a document or a record file; default: the
current folder). Reads add nothing to the record and open it read-only, so a
record in use is safe.

positional arguments:
  {summary,passes,notes,show,ideas,tried,results,compare,events,design,diff,similar,library,digest,gate,measure}
    summary             The loop in short: the baseline, the best per
                        objective and the standing pick, each against the
                        baseline at the same stage.
    passes              Each pass, oldest first: its search direction and why,
                        what it decided.
    notes               The operator's notes and the decisions' reasons,
                        oldest first.
    show                One design: its idea and why, every stage's numbers or
                        error, its trace files.
    ideas               The ideas notebook: each hypothesis, its status and
                        the evidence on record.
    tried               The designs tried, oldest first: the stages each
                        reached, its numbers or why it stopped.
    results             The measured designs at one stage, ranked by the
                        loop's objectives, with every metric each has (a
                        dictionary metric's cases as metric.case).
    compare             Designs side by side, metric by metric, the best on
                        each objective marked; how far each got and why it
                        stopped.
    events              The record's events: without --kind how many of each
                        kind; with it the last N of that kind (decision,
                        conclusion, pass, human_note, idea, decided:...), each
                        in short.
    design              A design's text as the record keeps it (a name, or the
                        start of one).
    diff                Two designs line by line; either may be a file.
    similar             The designs on record nearest a file (or a design):
                        how near each is, its idea, how it ended. Information,
                        never a verdict: a small change can still measure very
                        differently.
    library             The library's papers, one line each; with QUERY the
                        nearest, with their digests (the old name of `flux
                        library`, as it answered).
    digest              One paper's digest (by file name or stem; the old name
                        of `flux library digest`).
    gate                The loop's own gate on a file (inside a turn: a probe,
                        on its budget).
    measure             The loop's own stages on a file, each on its own
                        (inside a turn: a probe).

options:
  -h, --help            show this help message and exit

    flux loop results¶

    usage: flux loop results [-h] [--stage STAGE] [--top N] [--goals]
                         [--metrics M,...] [--match TEXT] [--by M]
                         [--loop LOOP] [--db DB] [--campaign CAMPAIGN]
                         [--part PART] [--json]

options:
  -h, --help           show this help message and exit
  --stage STAGE        The stage (default: the goal's, else the deepest

                       it reached, ranked at the goal's.

  --goals              Only the designs meeting every limit of the objectives.
  --metrics M,...      Only these metrics (a name takes its cases: sim_lost is
                       sim_lost and sim_lost.<case>).
  --match TEXT         Only the designs whose text, idea, rationale or refusal
                       says TEXT.
  --by M               Ranked by the one metric M instead (its objective's
                       direction, else the smaller first; --by=-M the larger
                       first).
  --loop LOOP          The loop's folder, document or record (*.db) (default:
                       the agent turn's, else the current folder).
  --db DB              The record (default: the loop's out/<id>.db).
  --campaign CAMPAIGN  A campaign id or prefix (default: the loop's).
  --part PART          One part (default: the turn's part, else every part /
                       the whole).

    flux knowledge¶

    usage: flux knowledge [-h] [--loop LOOP] [--project PROJECT] [--json]
                      [--topic TOPIC] [--from N]
                      {list,search,show,insights} ...

Reads the loop's library -- its library/ folder, the files and folders its
document lists (flow.knowledge.library), its projects' libraries -- one line
per file, and the accepted entries of the projects the loop is linked into, as
its run's start saw them (never a proposal); hidden paths never appear;
`insights` the run's conclusions from its record (knowledge.insights). Inside
an agent's turn it reads that turn's loop; elsewhere --loop (default: the
current folder). Plain text; --json for data.

positional arguments:
  {list,search,show,insights}
    list                The library's files, one line each, then each
                        project's topics and its entries' headlines (the
                        default).
    search              The library's files nearest some words, with their
                        best passages, and the entries matching them, each
                        whole (headline, analysis, designs).
    show                A library file by its name (where it is, its text from
                        a line on) or an entry, whole, by its id (#12 or 12).
    insights            What the run has concluded from its record so far
                        (knowledge.insights: by rules or an agent), as the
                        loop last made it.

options:
  -h, --help            show this help message and exit
  --loop LOOP           The loop's folder or document (default: the agent
                        turn's, else the current folder).
  --project PROJECT     One project, by its place (silicon@hw-lab) or address.
  --json                The answer as JSON.
  --topic TOPIC         One topic.
  --from N              The library's files from the N-th on.

    flux library¶

    usage: flux library [QUERY | digest PAPER | outline PAPER | read PAPER [--section S | --around QUERY | --lines A-B | --pages A-B | --from N]] [--n N] [--loop LOOP] [--json]

The loop's own library/ and every project library it reads
(library/<name>@<group>/), each document by its name there (booth.md,
silicon@hw-lab/x.pdf). With nothing: every document, one line each. With
QUERY: the nearest documents, each with its digest and its 3 best passages.
digest PAPER: its digest; outline PAPER: its sections with their pages and
lines; read PAPER: a section, the passages around a query, a range of lines
(or a PDF's pages), or from a line on. Every answer prints about 3000 tokens
at most; one cut ends with the command that continues. What the loop hides
from its agents is refused. Inside an agent's turn it reads that turn's loop;
elsewhere --loop (default: the current folder). Plain text; --json for data.

positional arguments:
  QUERY           Words to search for, or digest|outline|read and the PAPER.

options:
  -h, --help      show this help message and exit
  --n N           How many documents for a query (default 5).
  --section S     read: one section, by its id in the outline (3.2) or its
                  title.
  --around QUERY  read: the passages best matching QUERY, with a little
                  context.
  --lines A-B     read: lines A to B.
  --pages A-B     read: a PDF's pages A to B.
  --from N        read: from line N on (the list: from its N-th document).
  --loop LOOP     The loop's folder or document (default: the agent turn's,
                  else the current folder).
  --json          The answer as JSON.

    flux workbench¶

    usage: flux workbench [-h] {find,note} ...

The workbench's tools and notes found by more than their words: their paths'
words, a tool's docstring and help, a one-line description of each file's
subject with its synonyms, their text, and the parts and designs whose agent
turns wrote, ran or read them. Inside an agent's turn it reads that turn's
workbench; elsewhere --workbench or --loop (default: the current folder).
Plain text; --json for data. Reads only.

positional arguments:
  {find,note}
    find       The files most relevant to one need, said in one or more
               phrasings.
    note       Before writing a note: the note that already covers its subject
               (to update), or a new note's path.

options:
  -h, --help   show this help message and exit

    flux workbench find¶

    usage: flux workbench find [-h] [-n N] [--workbench WORKBENCH] [--loop LOOP]
                           [--db DB] [--json]
                           QUERY [QUERY ...]

Each QUERY is one phrasing of the same need (the operator's name, the method,
the math); their rankings are fused, so a file several reach comes first. Each
file: its path, its description, why it matched (the words each field has, its
best passage) and what the record says of it.

positional arguments:
  QUERY                 One phrasing of the need; quote one of several words.

options:
  -h, --help            show this help message and exit
  -n N                  At most N files (default 8).
  --workbench WORKBENCH
                        The workbench folder (default: the turn's, else the
                        loop's).
  --loop LOOP           The loop's folder or document (default: the agent
                        turn's, else the current folder).
  --db DB               The record to read the files' links from (default: the
                        loop's).
  --json                The answer as JSON.

    flux workbench note¶

    usage: flux workbench note [-h] [--workbench WORKBENCH] [--loop LOOP]
                           [--db DB] [--json]

Each SUBJECT is one phrasing of the note's subject (the operator and the
method or finding). The notes are ranked as `find` ranks them; a note covers
the subject when its name, description and first line hold most of one

description, last change, head) to update, else the path for a new note.

    flux task run¶

    usage: flux task run [-h] [--skill SKILL] [--db DB] [--steps STEPS]
                     [--repair REPAIR] [--model MODEL] [--replies REPLIES]
                     [--out OUT] [--no-structured] [--role ROLE=NAME]
                     [--agent HALF [HALF ...]] [--plan FILE] [--tui] [--think]
                     [--num-predict NUM_PREDICT] [--passes N]
                     [--tool-hops TOOL_HOPS] [--hop-share HOP_SHARE]
                     [--patience PATIENCE] [--regenerate PART [PART ...]]
                     [--screen-only] [--reevaluate]
                     [--reevaluate-scope {all,pending,failed}]
                     [--reevaluate-of ID] [--remeasure] [--rerun-baseline]
                     [--json FILE] [--no-prototype] [--no-patching]
                     [--no-sandbox]
                     file

positional arguments:
  file                  The problem's folder, or one of its documents
                        (problem.yaml, NAME.problem.yaml).

options:
  -h, --help            show this help message and exit
  --skill SKILL         A skill folder (SKILL.md), or a folder of them, beside
                        the document's own (repeatable).
  --db DB               Campaign record (default: <document dir>/out/<task
                        id>.db).
  --steps STEPS         Planner steps (default: the document's).
  --repair REPAIR       Repair attempts per generation.
  --model MODEL         The model name on the endpoint in use: the local
                        Ollama by default, or the server FLUX_REMOTE_BASE_URL
                        names.
  --replies REPLIES     A JSON list of scripted replies: runs without a model.
  --out OUT             Write the decided artifact here (default: <document
                        dir>/out/<task id><extension>).
  --no-structured       Plain decoding, no schema.
  --role ROLE=NAME      Switch who fills one of the four roles, repeatable:
                        --role orchestrator=rules. `flux task check` lists the
                        choices.
  --agent HALF [HALF ...]
                        The AGENT takes these halves: orchestrate (it picks
                        what next, which part, which improve option, with its
                        reasons on record), plan (it writes the loop plan the
                        pass follows); all for both. The model's tool calls
                        inside its turns are the document's budget.tools (on
                        by default).
  --plan FILE           A loop plan document to follow: parts, budget, stages,
                        roles, tools; a field set to "agent" is the agent's to
                        fill.
  --tui                 The curses screen: tasks, results, log, the r loop
                        toggle.
  --think               Ask the model for its reasoning on every turn.
  --num-predict NUM_PREDICT
                        Output tokens per turn (default 6000).
  --passes N            Stop after N passes. Default: the document's
                        `budget.passes`, else run until stopped (`flux stop`,
                        Ctrl-C, q in the TUI); a pass at rest is followed by
                        one that explores.
  --tool-hops TOOL_HOPS
                        Rounds of tool calls a turn may make.
  --hop-share HOP_SHARE
                        Share of the model's context window a round that may
                        call tools may write (0.5).
  --patience PATIENCE   Prototype turns granted after each new best.
  --regenerate PART [PART ...]
                        Parts to draft again instead of resuming from the
                        record; all for every part.
  --screen-only         Stop the chain at the synthesis screen.
  --reevaluate          At this start, after the baseline: check and measure
                        every design on record again -- the designs the loop's
                        Invalidate all set aside, else every design,
                        invalidated first -- then the passes; a stop keeps
                        what was measured and the next start continues.
  --reevaluate-scope {all,pending,failed}
                        With --reevaluate: `pending` or `failed` measures only
                        the designs re-measure pending (the round
                        Maintenance's Re-Evaluate wrote of them, what
                        Invalidate all set aside), never invalidating every
                        design.
  --reevaluate-of ID    Check and measure again the designs one invalidation
                        by hand took out (its id in Results).
  --remeasure           Measure again the designs a rejection asked to (the R
                        pass), then rest.
  --rerun-baseline      Measure pass 0 again though the document's baseline is
                        unchanged (otherwise the one on record stands).
  --json FILE           Also write the answer as JSON: the decision, the
                        frontier, what was refused, the application's own
                        result.
  --no-prototype        No prototype stage: the target directly.
  --no-patching         Repair by rewrite, not by edits.
  --no-sandbox          Run on this machine, not in the container sandbox
                        (Podman or Docker; also FLUX_SANDBOX=0).

Exit status: 0 a design meets every requirement (the decision, its artifact
written); 3 correct designs were measured but none meets every requirement yet
(no decision; the closest is reported, no artifact written); 1 no design was
measured, or the run could not start; 130 interrupted.
