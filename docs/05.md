## 1. Build vs. reuse vs. adapt

| Component | Decision | Rationale |
|---|---|---|
| Distributed orchestration, fault tolerance, cluster mgmt | **Reuse** — CHIA/Ray | Solved, battle-tested at 28 machines / 1024 cores across on-prem + AWS. Rebuilding is pure cost. |
| Containerised isolation of agents from evaluators | **Reuse** — CHIA pattern | Threat model and mechanism already validated; also collapses env setup from ~1h to seconds. |
| Agent tool protocol | **Reuse** — MCP via fastmcp | Same stack CHIA uses; interoperates immediately. |
| Energy primitive estimation | **Reuse** — Accelergy plug-ins | CACTI/Aladdin/NeuroSim ecosystem already exists. Don't recreate it. |
| Cycle-exact ground truth | **Reuse** — Verilator, FireSim, gem5 | Via CHIA nodes. |
| Physical design / PPA truth | **Reuse** — Hammer | Fronts commercial CAD; already a CHIA library node. |
| Workload ingest | **Reuse** — ONNX + MLIR importers | Frontend only, not internal IR. |
| Single-core analytical cost model | **Adapt then replace** — ZigZag | Adapter on day 1 (instant capability incl. uneven mapping + IMC); native Rust core later for speed. |
| Multi-core / layer-fusion model | **Adapt** — Stream/COALA | Validated against three real accelerators. Do not reimplement. |
| Cross-validation oracle | **Adapt** — Timeloop+Accelergy | Needed precisely to detect when we disagree with the field's baseline. |
| Sparsity / CiM | **Adapt** — Sparseloop, CiMLoop | Mature, well-characterised. |
| Search strategies | **Build the plug-in layer, port the strategies** | LOMA, CoSA (MIP), DOSA (gradient) all exist as stranded implementations. |
| **IR (workload/arch/mapping)** | **BUILD** | Does not exist. This is the product. |
| **Evaluator ABI + conformance suite** | **BUILD** | Does not exist. This is the product. |
| **Calibration / uncertainty / escalation** | **BUILD** | Does not exist anywhere. Highest differentiation. |
| **Result & provenance store** | **BUILD** (thin) | SQLite/Postgres/S3 backends CHIA already supports. |
| **Benchmark corpus + holdout discipline** | **BUILD** | Community artifact; also our own regression safety net. |
| RTL generation | **Adapt, then build** ([D2](00-decisions.md)) | Adapt existing generators (Gemmini's, CIRCT/Chisel flows CHIA already wraps) first; add an LLM-agent generation strategy once calibration + validity checking are live. Conformance-checking (G7) becomes the acceptance gate, not a separate deferred feature. |
| Knowledge/context layer | **BUILD** ([D3](00-decisions.md)) | Does not exist. RAG-style retrieval over specs/standards/protocols, exposed to agents the same three-surfaces way as everything else. |
| NoC model | **Adapt** ([D6](00-decisions.md)) | `evaluators/booksim` — real 2D/3D k-ary n-cube topology + routing simulation via Booksim2, done. |
| Thermal model | **Defer / integrate** | 3D-ICE integration when needed — the real gap left by D6: NoC topology/routing is simulated now, TSV placement / inter-die links / thermal are not. Priority raised relative to other Tier-2 coverage per [D1](00-decisions.md) (SoC-level DSE is now core scope, not edge-vs-datacentre only). |

## 2. Phased plan

### Phase 0 — Decide (2–3 weeks) — **done, see [00](00-decisions.md)**

Resolved the four open questions from [01 §9](01-landscape.md): target domain is full SoC-level
DSE, not edge-vs-datacentre only (D1); generation closure is in scope (D2); "training" is
reinterpreted as a knowledge/context layer, DNN training itself stays out of v1 (D3). Licensing
floor check is still **open** — do it before any vendoring, per
[00's still-open items](00-decisions.md).

Deliverable: [00 — Phase 0 Decision Record](00-decisions.md).

### Phase 1 — Spine (6–8 weeks)

Prove the contract works before optimising anything.

- IR v0.1 schemas for workload / architecture / mapping, with canonicalisation + hashing.
- Evaluator ABI v0.1 including the `Estimate`/`validity`/`bottleneck`/`provenance` return shape.
- **Two adapters: ZigZag and Timeloop+Accelergy.** Two is the minimum that proves substitutability;
  one proves nothing.
- Conformance test suite. Includes the canonical disagreement case: an uneven mapping that ZigZag
  can express and Timeloop cannot — the adapter must fail loudly with
  `not_expressible_in: [timeloop]`, not silently approximate.
- ONNX frontend. Result store (SQLite) with full lineage.
- CLI: `flux eval`, `flux import`, `flux replay`.
- **Knowledge layer, small and hand-picked ([D3](00-decisions.md)).** Ingest + retrieval for a
  first, narrow spec corpus (e.g. AMBA AXI4, JEDEC DDR/LPDDR basics, RISC-V unprivileged ISA);
  expose `knowledge_lookup` the same three-surfaces way as `evaluate`. Starts now, not as a late
  add-on, because Phase 3.5 generation will depend on it.

**Exit criterion.** Take a published ZigZag result, reproduce it through the ABI, then re-evaluate
the *same IR* through Timeloop, and produce a quantified disagreement report. If that report is
boring and correct, the contract works.

### Phase 2 — Fidelity (8–10 weeks)

The differentiating phase.

- Calibration store; validated-domain descriptors; residual models per regime.
- Uncertainty propagation into `Estimate`; `in_domain` computation.
- Escalation policy + rung selector; RTL-sim (Verilator) and Hammer-synth adapters wired as
  higher rungs via CHIA nodes.
- Drift-detection CI over the calibration corpus.
- **Calibrate against real silicon/RTL**, reproducing the field's own bar: ZigZag's ≤6% energy /
  ≤9% utilisation vs RTL, and its 5–7.5% vs published Eyeriss/ENVISION. Add Gemmini RTL as a target
  (it's the standard, and DOSA already validated against it).

**Exit criterion.** For a design point outside the validated domain, the tool says so, escalates,
measures, and tightens its own future intervals — demonstrably, in CI.

### Phase 3 — Search and speed (8–10 weeks)

- Strategy plug-in layer; port exhaustive, LOMA-style, annealing, CP/MIP, gradient (DOSA-style).
- `evaluate_batch`; content-addressed memoisation; incremental re-evaluation.
- Rust native backend for the dense affine path.
- Warm-start from the result store; budget-aware search (wall-clock + USD).

**Exit criterion.** ≥10⁵ evaluations/s/core on the native path; a head-to-head strategy comparison
on identical problems with identical evaluators — the first apples-to-apples DSE search benchmark
in this field.

### Phase 3.5 — Generation ([D2](00-decisions.md)) (6–8 weeks)

New phase, not in the original proposal. **Gated**: do not start until Phase 2's calibration/
escalation machinery and Phase 4's independent validity checker + holdout corpus are live for the
workload classes being generated — generating RTL against a cost function an agent can already game
is exactly CHIA's documented AlphaEvolve reward-hacking failure, reproduced on purpose.

- Adapt existing generators first: Gemmini's own generator, CIRCT/Chisel-based flows CHIA already
  wraps. Write a from-scratch generator only where nothing adaptable exists.
- LLM-agent generation strategy, grounded by the knowledge layer (`knowledge_lookup` calls before
  proposing a candidate).
- Every generated design gates through the existing G7 conformance suite
  (`generation/conformance/`) — the same suite evaluator backends must pass, not a separate looser
  standard.

**Exit criterion.** A generation run produces a candidate that (a) passes independent validity
checking, (b) passes RTL conformance against its declared model within the calibrated uncertainty
band, (c) is deterministically replayable, and (d) the run's pass rate is tracked as the KPI in
[§4](#4-kpis) below.

### Phase 4 — Agentic integration (6–8 weeks)

- CHIA library nodes (`flux_evaluate`, `flux_search`, `flux_calibrate`,
  `flux_conformance_check`) + Dockerfiles; contribute upstream. **`flux_evaluate` is pulled
  forward and done ([00-decisions.md D5](00-decisions.md))** — a real `@ChiaFunction()` node,
  verified against a real local Ray instance. The other three, and holdout-corpus-aware
  Dockerfiles, remain here.
- MCP tool surface generated from the same definitions.
- Independent validity checker; holdout corpus enforcement; redaction policy for
  PDK-derived metrics.
- Reference CHIA loop: agentic accelerator DSE with an analytic→RTL→synthesis evaluator cascade
  and anti-reward-hacking guarantees. **This is the demo that makes the case.**

**Exit criterion.** An agentic search run that (a) produces a design better than the best
human-tuned baseline, (b) whose winning design passes independent validity checking and RTL
conformance, (c) whose result is deterministically replayable, and (d) costs a reportable number
of dollars.

### Phase 5 — Coverage (ongoing)

Stream/multi-core adapter · Sparseloop/CiMLoop adapters · MLIR frontend · LLM workload features
(KV cache, prefill/decode asymmetry, dynamic seq-len distributions, MoE) · NoC model (2D/3D
topology + routing now real via `evaluators/booksim`, [00-decisions.md D6](00-decisions.md) —
TSV placement and inter-die link modelling still open) · thermal via 3D-ICE · chiplet/D2D ·
public benchmark + leaderboard.

## 3. Validation methodology

Non-negotiable, because this is the part the field does badly.

1. **Three-way validation, as ZigZag itself did**: (a) against published taped-out chip
   measurements, (b) against in-house post-synthesis/RTL data, (c) against other frameworks.
   We add (d): against the *same* framework at a different fidelity rung.
2. **Holdout discipline.** A partition of the corpus is never visible to search or to any agent.
   This is precisely how CHIA caught its gem5-alignment agent overfitting — the agent tuned a
   threshold "calibrated to [training benchmark]'s inner loop," which then degraded a holdout
   benchmark it could not see.
3. **Many small benchmarks beat few large ones for alignment.** CHIA's hypothesis, borne out in
   their results: with a large suite of small, targeted benchmarks, over- and under-estimates
   cannot cancel out. Build the corpus accordingly.
4. **Cross-node generalisation must be tested explicitly.** CHIA's Sky130 optimisations did not
   transfer to commercial 16nm beyond the first change. Any calibration claim must state which
   technology class it holds for.
5. **Adversarial validation.** Run an unconstrained evolutionary agent against the evaluator with
   the explicit goal of finding a design the model loves and RTL hates. Every hole it finds becomes
   a validity-checker rule and a corpus entry. Do this *before* release, not after.

## 4. KPIs

| Category | Metric | Target |
|---|---|---|
| Correctness | Analytic vs RTL error, in-domain | ≤10% latency, ≤10% energy |
| Correctness | Calibrated CI coverage (true value inside CI) | ≥90% |
| Correctness | Out-of-domain detection recall | ≥90% |
| Speed | Dense mapping evals/s/core (native) | ≥10⁵ |
| Speed | Full model × arch sweep, previously hours | ≤10 min |
| Speed | Cache hit rate on repeated sweeps | ≥80% |
| Substitutability | Backends passing conformance suite | ≥4 at v1 |
| Generation ([D2](00-decisions.md)) | Generated designs passing independent validity + RTL conformance | ≥90% before a generation strategy is considered production-usable |
| Search | EDP vs random search baseline | ≥2.8× (DOSA's published margin) |
| Search | Best-design-per-dollar vs. naive agentic loop | ≥3× |
| Reproducibility | Published results replayable by one command | 100% |
| Adoption | Time from `pip install` to first result | ≤5 min |
| Adoption | External backends/strategies contributed | ≥2 in year 1 |

## 5. Risks

| Risk | Severity | Mitigation |
|---|---|---|
| **The IR becomes a lowest-common-denominator** and loses ZigZag's uneven mapping or Stream's fusion | High | Design IR as a *superset* with explicit `compatibility` metadata; adapters fail loudly rather than approximate; conformance suite includes the inexpressible cases by construction |
| **ArchGym precedent** — a "contract" framework that the field politely ignored | High | Ship *capability*, not just abstraction: Phase 1 must give an existing CHIA user something they cannot get today. Contract adoption follows utility, never the reverse |
| Upstream churn breaks adapters | Medium | Pin versions; conformance suite runs against pinned + latest in CI; adapters are thin and independently installable |
| Calibration data is expensive to obtain | Medium | Start with what's public (Eyeriss, ENVISION, Gemmini RTL, Stream's three validated accelerators); active-learning escalation spends the budget only where it changes the answer |
| Rust core is premature optimisation | Medium | Phase 3, not Phase 1. Adapters first; profile; then rewrite the hot path only |
| Generation ([D2](00-decisions.md)) reward-hacks the evaluator | High | Generation is in scope but strictly gated behind Phase 2 calibration + Phase 4 validity checker (Phase 3.5 exit criterion); every generated design must pass the same conformance suite as any other candidate, never a looser one |
| Team lacks a real silicon target | High | Partner early — Gemmini (Berkeley), Snitch/Siracusa (ETH/UniBO), X-HEEP-based designs (EPFL/UPM/PoliTo) are all open and all have published measurements |
| Licence incompatibility on vendored code | Low–Medium | Adapters call, never vendor; legal review in Phase 0 |
| Agents reward-hack our evaluator | High | Independent validity checker, structural isolation, holdout corpus, adversarial validation before release |
| Domain choice is deferred and the IR forks badly | High | **Resolved** — [D1](00-decisions.md): full SoC-level DSE, IR designed as the general superset, Phase 1 spine still validated against the DNN-accelerator corpus first for fastest ground truth |

## 7. The 90-second pitch

> Accelerator design-space exploration has a dozen good cost models and no way to compare them,
> substitute them, or trust them outside the handful of designs each was validated against. That
> was survivable when a human looked at every result. It is not survivable now that agents generate
> thousands of candidates and optimise straight into whatever region the model is most wrong about.
>
> We're building the missing middle: a shared IR for workloads, architectures, and mappings; a
> narrow evaluator contract that makes ZigZag, Timeloop, Sparseloop, RTL simulation, and synthesis
> interchangeable behind one interface; and a calibration layer that attaches an honest confidence
> interval to every number and escalates to higher fidelity exactly when it matters.
>
> We're not rebuilding orchestration — CHIA solved that. We're not rebuilding cost models — we're
> adapting the good ones. We're building the layer that makes them composable, comparable, fast,
> and safe to point an agent at.
