    Configure¶

    Write the document (problem.yaml) and the scripts it names, in the web app: the configurator (Settings › Problem › Configurator, or New loop › Configurator) fills it step by step, and Direct edit shows it as YAML. Start from the first loop, an agent's draft (Write a loop with an agent), or New loop › Create or upload. Defaults and allowed values: Document reference.

    Where files go (upload them in Files, or write one with New under the configurator's Files):

    Folder Holds
    beside the document The scripts it names
    library/ Papers and specs
    knowledge/ Method notes
    tests/ The gate's tests (hidden from agents)
    lib/src/<package>/ A Python package the commands import (lib/src is on the Python path)

    Check flags any other file no document names (a file the loop hides is named by its hidden setting): delete it or name it.

    Define the goal and interface¶

    • statement: the goal.
    • contract: the interface and restrictions (signature or ports, inputs, accuracy, rules).
    • artifact: the design's file name (design.py, design.sv, kernel.cu). Its extension is every design's. RTL presets imply design.sv; with your own scripts, say it (else .txt).
    • Correctness comes from flow.check, not prose.
    statement: Find a fast implementation of count_primes(n).
contract: >-
  Export count_primes(n). Return the number of primes strictly below n for
  nonnegative integer n. Do not change the interface or the benchmark.
artifact: design.py

    Choose how designs are made¶

    Approach Configuration Use it when
    Script design: {run: "..."} You can render each parameter into a design
    FluxAgent design: flux You want generated code or algorithms; the default
    Coding agent design: claude (also codex, opencode) The design needs edits across files or interactive checks
    Fixed candidates design: {catalog: [...]} You already have artifacts to compare
    Tune settings A search space, no generator Commands use the chosen settings directly

    A script writes {artifact} (its stdout is ignored):

    flow:
  design:
    run: ["{python}", "{home}/render.py", "{artifact}", "{block}"]
    • The search supplies {block}. {point} gives the whole point as a JSON file; {vars} your shared settings. See Search and agents.
    • A command is a string or a list. A string is split into arguments, not run by a shell: for a pipeline use a script or bash -c. Use lists when values contain spaces.
    • A command starting with flux uses the loop's own Flux.

    Build a gate, cheapest check first¶

    Checks run in order; the first failure refuses the design.

    flow:
  check:
    build: "{python} -m py_compile {artifact}"
    correctness:
      run: "{python} {home}/check.py {artifact}"
      timeout_s: 120
    Result Meaning
    Any nonzero exit of a check named build Did not build
    Exit 3 from any check Did not build
    N failing in the output N failures
    Otherwise Exit 0 passes; nonzero is one failure

    stderr output alone is never a failure. For another output format:

    flow:
  check:
    tests:
      run: "{python} {home}/check.py {artifact}"
      count_re: 'failures=(\d+)'
    • count_re captures a failure count; fail_re counts matching lines.
    • Both scan stdout and stderr, and can fail a design that exits 0. Keep debug text distinct.

    For RTL, put the ports and reference function in golden.py:

    flow:
  check:
    lint: "fluxpreset rtl lint {artifact}"
    golden: "fluxpreset golden {artifact} --golden {home}/golden.py"
    • Golden model: vectors, clocked designs, float tolerances.
    • The configurator offers the built-in checks under Flux presets (a check's Type, a measurement's Tool).

    Measure surviving designs¶

    Stages run in document order. Put the cheap screen first, the costly one last. A stage prints the metrics it declares (e.g. time_ms=2.31 bytes=2048, on stdout or stderr):

    flow:
  measure:
    screen:
      run: "{python} {home}/bench.py {artifact} --quick"
      metrics: [time_ms, bytes]
      cutoff: {metric: bytes, below: 4096}
    confirm:
      run: "{python} {home}/bench.py {artifact} --full"
      metrics: [time_ms, bytes]
      timeout_s: 1800
    • --quick and --full are your benchmark's own flags.
    • A nonzero exit fails the measurement: no numbers taken, the design refused at that stage (kept on the record; ✗ in Live).
    • metrics_re reads another output format.
    • Every stage declares the metrics its objectives need.

    Presets (Presets) and needs for required tools:

    flow:
  measure:
    screen:
      run: "fluxpreset rtl measure {artifact} --stage synth --clock-ps 1000"
      metrics: [fmax_mhz, area_um2, power_w, cell_count]
      needs: [yosys, openroad]
    confirm:
      run: "fluxpreset rtl measure {artifact} --stage place --clock-ps 1000"
      metrics: [fmax_mhz, area_um2, power_w, cell_count]
      needs: [yosys, openroad]
      timeout_s: 1800

    A stage whose needs tool is missing is skipped: check which stage a number came from.

    Cutoffs and estimates¶

    cutoff decides whether a design goes on: at (minimum), below (maximum), within (a fraction of the best). A list needs all:

    cutoff:
  - {metric: fmax_mhz, at: 1000}
  - {metric: area_um2, below: 80}

    estimate screens before paying for the tool:

    estimate: {kind: surrogate, margin: 0.05}
    • The surrogate uses earlier measurements at that stage (at least three).
    • A design estimated outside a cutoff or limit by more than margin skips the stage.
    • Estimates are not measurements. Command and model estimators: reference.

    Define what wins¶

    An objective with goal is a limit; without, a preference:

    objectives:
  - {metric: fmax_mhz, direction: maximize, goal: 1000}
  - {metric: area_um2, direction: minimize, goal: 80}
  - {metric: power_w, direction: minimize}
    • Here: at least 1000 MHz, at most 80 µm², then least power.
    • Preferences are compared in written order.
    • A goal uses the deepest stage unless stage names another.
    • If nothing meets every limit, the report shows the closest design and its shortfall; no decision artifact is written.
    • balance: true on several goal-less objectives picks the frontier's knee.
    • A relative limit: {metric: speedup, direction: maximize, keep: 0.9, above: 1.0} keeps 90% of the best gain over the baseline.
    • An objective with neither direction nor goal is tracked: {metric: ipc, unit: ipc} is measured and shown with the others, never ranked (Configure: Tracked (not ranked)).

    Control time and concurrency¶

    budget:
  passes: 10
  repairs_per_design: 6
  tools_at_once: 1
    Key Bounds
    passes The run (one design per pass; omit or 0 to run until stopped)
    repairs_per_design Attempts to fix one design
    tools_at_once Tool runs at once across the loop: checks, measurements, agent probes -- and so the designs evaluated at once

    Designs made at once is Design's list: each agent listed is one session (by: [claude, claude]: two lanes; passes: 6 then makes six designs, two at a time).

    • Keep timings isolated with tools_at_once: 1.
    • Configurator: Extra › Running.
    • Meeting a goal or a stalled search does not end an unlimited run (Run, stop, resume).
    • More: budget reference.

    Configurator, Graph step: Runs as Passes | Trunk. Trunk writes trunk: instead of flow: (passes or a trunk).

    • Design gives each agent its own Model, Thinking and effort; + Add an agent adds one (the same agent with another model too: by: [claude, {by: claude, model: opus}]).
    • Under Trunk, each agent of Design's list is a trunk; Extra › Running's Tool runs at once counts branches, and Search becomes a bud every 10 designs when an agent works it.
    • Back to Passes, Design keeps its first agent and model.
    • The switch is disabled, naming why, when trunk mode cannot run the loop (a parameter search, Plan, Design not by a coding agent).

    Add context and reusable settings¶

    vars: {input_size: 1000000, repetitions: 9}
flow:
  knowledge:
    library: [spec.md, reference.py]
    hidden: [check.py]
    • vars reaches scripts as the {vars} JSON file.
    • knowledge.library joins the library, which agents read on demand.
    • knowledge.hidden hides the gate's files from agents.
    • More: Knowledge, skills, hidden paths.

    Then Settings › Problem › Check, and Start with one pass (Run, stop, resume).
