    Run, stop, resume¶

    Check, start, stop and read a loop in the web app. Everything here is on a loop's page: the Start, Stop and Restart buttons in its header, Settings › Problem › Check, and the Overview, Live and Results tabs (Tour).

    Check before running¶

    Settings › Problem › Check validates the document and lists its stages, checks, objectives, tools and model. It runs no candidate check or measurement; a one-pass run does that.

    • Every file the document names must be in the loop (a missing one is listed with its key).
    • The golden model must run.
    • A document that does not load, a missing file or a refused setting is listed with where it is set; the configurator marks it on its step (Issues).
    • It runs in the sandbox.
    • Start runs the same check first when the inputs changed; on failure its button reads Start anyway.

    A loop has problem.yaml; extra NAME.problem.yaml files are other problems with their own records. Settings › Problem edits one at a time, and Start asks which one runs.

    Start¶

    Start asks how many passes (one design each) or Until stopped.

    • A start resumes from the record: unchanged measurements are reused.
    • A trunk asks for designs and says what runs ("trunk: 2 agents, 3 branches at once, 6 may wait"); one branch at once while parallel work is off.
    • Settings › Record › Re-Evaluate checks and measures again every design on the record (or only some Results tabs), and with Rerun baseline the baseline (pass 0), before the passes (Results).
    • Who works each box, which model, thinking, budgets: the document (Configure); the run's resources: Settings › Advanced (admins).

    Stop, resume, and keep experiments separate¶

    An unlimited run goes on until stopped. Meeting an objective or a stalled search does not stop it.

    • Stop and Restart act after the current pass: an amber pill says "Stops after pass 4". Press the same button again to act now; the pass is abandoned.
    • Resume: Start again; unchanged measurements are reused.
    • One run per record: a second start is refused while a run holds the record; so are Delete, Rename, Reset, Archive and Replace.
    • Trunk: Stop ends agent turns, lets running branches finish and keeps the queue. Stop now ends everything; the next start runs the interrupted designs first.
    • Separate experiment: New loop › Clone copies a loop's problem without its runs. Settings › Preferences › Archive, reset or delete › Reset keeps the document and scripts and asks what else to keep.

    When a measurement still counts¶

    A measurement counts (decision, ranking, best, charts) until its stage changes:

    • the measure command (its words; not spacing, quoting or comments);
    • how numbers are read (metrics / metrics_re, a dictionary's aggregate);
    • its parameters (vars:, when the command takes {vars});
    • its input files (files and scripts the command uses);
    • its tools (the build of each program the stage runs or needs).

    Nothing else makes it stale: not prompts, other stages, checks, objectives, cutoffs, agents, budgets, names, comments or unread files.

    • A change is judged at the next start, or at once when saved in the web app while the loop is stopped. Pages show the last judgement and when it was made.
    • Stale measurements stay in Results, muted, marked "measured before a change". The decision and charts leave them out.
    • Overview shows a card ("12 designs were measured before a change to how synth is measured (the measure command and input file a.txt)"). The owner or an editor picks:
      • Accept as current: they count again (audited);
      • Leave as stale: card closed until the next change;
      • Re-measure: checked and measured again, by the running loop at its next free place, beside the designs it is making, one stale design at a time (a loop making one design at a time does it between two passes), or by a new run, designs_at_once of them at once.

    Older loops¶

    This Flux reads records from version 7 and loop files from the format of Nov 12, 2026.

    Refused Do
    An older record or loop file Open it in Flux 9957e3728, start it (or Compact and check), export again
    A loop file naming a box the loader's way (generate:, orchestrate:, ...) or saying params: Import it into Flux fdfd1faf0, migrate (Server › Old data › Migrate), export again
    A document with an older key Flux e7a0f9cba says what became of the key

    Moving a loop in one file¶

    Export (in Settings) writes one .zip, Loop only or Full; Import on another loop replaces its contents from one (Export and import). Import keeps the loop's name and settings, runs nothing, and changes nothing on refusal (an older or newer file, a record before version 7, an old box name).

    Read the result¶

    • Overview: the decision against your limits, the best designs, the best so far over time (Tour).
    • Results: every design measured, ranked; charts; compare designs side by side; the ideas notebook (Results).
    • Live: passes, tools and agents, now and for every earlier start; its Start picker opens an older one (Live).
    • Agents: every model and agent turn: prompt, reply, tool calls, time, tokens.
    • Chat: ask an agent about the loop (why it stalls, which design is best); it reads the loop and changes nothing (A loop's Chat).

    The decision's artifact is written under out/ only when a design meets every requirement. Estimates and screening numbers are not confirmed measurements.

    The run ends with Meaning
    ✓ accepted A measured design meets every requirement; the decision artifact is written
    ! closest Correct designs were measured, but none meets every requirement; Overview shows the shortfall
    ✗ failed No design was measured, or the run could not start; Why it stopped says why

    Sandbox¶

    Checks, runs, New loop › Agent and Chat's agents run in a container: agents and the loop's own code cannot touch the rest of the server's machine. Engine: rootless Podman, else Docker. Without either: the sandbox needs Podman or Docker.
    Sees The host read-only: system, /nix/store, Flux, programs on PATH, the loop's folder
    Writes Only the loop's out/, workbench/ and cache. Scratch is deleted after the run and capped by Scratch /tmp size (Admin › Runtime › Sandbox, or the loop's Settings › Advanced)
    Home Flux's agent config and logins, not yours: no ~/.ssh, other repositories or Docker socket
    Network The host's, or an allowlist of hosts, domains and networks; direct TCP/UDP to them on request; the server's proxy. Admin › Runtime › Sandbox, Proxy; a loop's extra hosts in Settings › Advanced
    Limits Memory, CPUs, processes and scratch size: the loop's Settings › Advanced, else the server's defaults, never above its maximum (Sandbox limits, The memory guard)
    Off Settings › Advanced (admins): runs on the server as its account. Trusted code only

    When the sandbox cannot start¶

    Why it stopped on the Overview says what the engine said and what to do (the podman sandbox cannot start: ...). Flux repairs Podman's state itself when no Flux container runs, and logs it. The system service's installer prepares rootless Podman for its account; for anything else, ask the server's admin.

    When an agent's endpoint fails¶

    • Down or busy (the server answers 5xx or 429, or cannot be reached): the agent's turn waits for the endpoint and then goes on in the same session; no try is spent. All the loops and lanes using that endpoint wait together, and one of them checks it, every 5 s at first and then less often (every 15 s and up for 429). Live's row says waiting for endpoint ... down since 10:02. After 30 minutes the pass ends and the loop waits until the endpoint answers; Stop ends it at once.
    • Refused (its login is refused, its account has no quota left, its model is not offered, or the endpoint is not on the sandbox's network allowlist): retrying cannot help, so the pass ends and the next pass tries once more. Refused again, the loop stops: Why it stopped says what was refused and where to fix it (Account › Agents or Admin › Agents, Admin › Sandbox).

    Compiling¶

    Flux sets three things for every tool it runs (sandboxed or not):

    • MAKEFLAGS is cleared. An inherited -j would make Verilator build one file at a time. Never put -j in MAKEFLAGS.
    • FLUX_JOBS is the parallelism to use: make -j"$FLUX_JOBS", verilator --build-jobs "$FLUX_JOBS", cmake --build . -j "$FLUX_JOBS", ninja -j "$FLUX_JOBS". It is the step's resource hint cores (needs: {cores: 8} on the check or stage, or loop-wide; capped by the sandbox), else 1 -- so a compile-heavy step that states no cores builds about 2× slower, even on an idle machine. To build with more jobs, state the cores. Every loop's and user's steps on the machine count those cores in one pool, so together they never use more cores than the machine has.
    • ccache is on, one cache per user (ccache/<user> in Flux's cache folder, 10 GB max), never shared between users. Verilator uses it automatically. Other builds: CC="ccache gcc" CXX="ccache g++", or PATH="$FLUX_CCACHE_BIN:$PATH" (wraps gcc, g++, cc, c++, clang, clang++). Live shows hits and misses; Admin › Activity › Resources shows cache sizes.

    Built-in presets also reuse one design's work within a pass: rtl measure --stage place after --stage synth at the same clock continues from synthesis; rtl power, energy, path and breakdown read an existing stage; rtl cycles, power and energy reuse the golden test's model. Measure a design's stages at the same --clock-ps to benefit. Nothing is shared across designs, loops or users, and no number changes.

    System service¶

    Installing a team server: Install › System service. Updates are a button: Admin › Server › Version. A toolchain change builds the new environment while the old server keeps serving; running loops finish on their version.

    Where a loop's files are¶

    folder what is in it
    out/ the results: designs, measurements, decisions
    runs/ the log, the notes, the answer, the loop's conversations
    workbench/ the agents' notes and tools

    Everything else is scratch the clean-ups may delete.
