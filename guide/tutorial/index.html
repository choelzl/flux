    First loop¶

    Build a loop that compares two ways to sum the squares below n: a loop and a formula. Flux makes both, tests them, times them, and keeps the faster passing one.

    Needs a Flux server and a browser. No model, no hardware tools.

    1. Open the web app¶

    Install and start Flux (Install), open its address and sign in.

    The loop runs only your own scripts, so it can run without the sandbox: an admin switches it off for the loop in Settings › Advanced. With Podman or Docker on the server, leave it on.

    2. Create the loop and its document¶

    On the Loops list, New loop › Create or upload. Open Paste YAML, name the loop sums, paste this document and press Create from YAML:

    statement: Find the fastest correct sum_squares(n) implementation.
contract: >-
  Provide sum_squares(n) for nonnegative integers n. Return the exact integer
  sum of i*i for 0 <= i < n. Keep the function name and signature.
artifact: design.py

flow:
  search:
    method: sweep
    space:
      implementation: [loop, formula]
  design:
    run: ["{python}", "{home}/render.py", "{artifact}", "{implementation}"]
  check:
    correctness: "{python} {home}/check.py {artifact}"
  measure:
    bench:
      run: "{python} {home}/bench.py {artifact}"
      metrics: [time_ms]

objectives:
  - {metric: time_ms, direction: minimize}

budget: {passes: 2, tries_per_pass: 1, tools_at_once: 1}
    • The loop's name, sums, is its id. There is no id field.
    • The sweep proposes both space choices in its first pass.
    • passes: 2 is a cap: the run ends when the sweep has nothing left.
    • tools_at_once: 1 keeps timings from competing.

    3. Write the generator¶

    The loop opens on its Overview. Add the three scripts below: write each on your computer and drop it on Files › All files (or use its Files upload button), or write it in the browser with New under the configurator's Files (Settings › Problem › Configurator › Prompt).

    render.py:

    import sys
from pathlib import Path

implementations = {
    "loop": "sum(i * i for i in range(n))",
    "formula": "n * (n - 1) * (2 * n - 1) // 6",
}
expression = implementations[sys.argv[2]]
Path(sys.argv[1]).write_text(f"def sum_squares(n):\n    return {expression}\n")
    • {implementation}: the chosen value.
    • {artifact}: where the script writes the design.
    • {home}: the loop folder. {python}: the interpreter running Flux.

    More in command placeholders.

    4. Write the correctness check¶

    check.py:

    import importlib.util
import sys

try:
    spec = importlib.util.spec_from_file_location("candidate", sys.argv[1])
    candidate = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(candidate)
    function = candidate.sum_squares
except Exception as exc:
    print(f"did not load: {exc}")
    sys.exit(3)

failures = 0
for n in [0, 1, 2, 10, 100, 1000]:
    expected = sum(i * i for i in range(n))
    try:
        actual = function(n)
    except Exception as exc:
        actual = repr(exc)
    if actual != expected:
        failures += 1
        print(f"FAIL n={n}: got {actual!r}, expected {expected}")
print(f"{failures} failing")
sys.exit(1 if failures else 0)

    This is the gate: a failing design never reaches the benchmark.

    • Exit 3: the design did not build or load.
    • Exit 1: it loaded but failed the tests.

    5. Write the measurement¶

    bench.py:

    import importlib.util
import sys
import time

spec = importlib.util.spec_from_file_location("candidate", sys.argv[1])
candidate = importlib.util.module_from_spec(spec)
spec.loader.exec_module(candidate)
candidate.sum_squares(1_000_000)  # warm up

times = []
for _ in range(9):
    started = time.perf_counter()
    candidate.sum_squares(1_000_000)
    times.append((time.perf_counter() - started) * 1000)
print(f"time_ms={min(times):.6f}")

    metrics: [time_ms] tells Flux which name=value to read; the objective minimizes it. The workload, repetitions and statistic are yours to choose.

    6. Check, run, and inspect¶

    1. Settings › Problem › Check validates the document and lists what it needs: every file it names, its checks, stages and objectives. It runs no test or benchmark.
    2. Start (▶ in the loop's header) asks how many passes: choose 2 and start. Each pass checks and times one design; the run ends when the sweep has nothing left. The formula should win.
    3. Overview shows the decision and the best design; Results lists both designs with their checks and time_ms; Live shows each pass's steps and their output.

    What the run keeps, under Files › All files:

    File Contents
    out/sums.py The chosen passing design
    out/sums.db The record: every design, check and measurement
    runs/ The log, the notes and the answer

    Start again to go on: unchanged measurements are reused. For a separate experiment, Clone the loop from New loop (its problem, without its runs), or Settings › Preferences › Archive, reset or delete › Reset.

    Change the loop¶

    • Add an implementation to render.py and space.implementation: the next run measures it.
    • Replace the generator with an agent, add a measurement stage, or add a limit.
