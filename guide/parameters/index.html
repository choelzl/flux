    Document¶

    Every key of a loop's document, problem.yaml. Why to choose each: Configure. Validate with Settings › Problem › Check in the web app.

    The document at a glance¶

    Only statement is required. A complete document:

    statement: Count the primes below n, as fast as possible.  # (1)!
contract: >-  # (2)!
  A Python module defining count_primes(n) that returns
  exactly how many primes are below n.
artifact: design.py

flow:  # (3)!
  search:
    method: sweep
    space: {method: [trial_division, sieve, slice_sieve]}
  design:
    run: "{python} {home}/render.py {artifact} {method}"
  check:  # (4)!
    build: "{python} -m py_compile {artifact}"
    correctness:
      run: "{python} {home}/check.py {artifact}"
      timeout_s: 60
  measure:  # (5)!
    quick:
      run: "{python} {home}/bench.py {artifact} 50000"
      metrics: [time_ms]
      cutoff: {metric: time_ms, below: 20}
    full:
      run: "{python} {home}/bench.py {artifact} 1000000"
      metrics: [time_ms]

objectives:  # (6)!
  - {metric: time_ms, direction: minimize, goal: 20}

budget: {passes: 5, tools_at_once: 1}  # (7)!
vars: {n_max: 1000000}    # (8)!
    1. What to make. The only required field.
    2. Rules every design must follow: names, ports, what is forbidden.
    3. Who does each box of the loop: here a search over three methods, and a script that writes each design (flow settings).
    4. The checks, in order; the first that fails refuses the design (check settings).
    5. The measurements, cheapest first. cutoff decides which designs go on to the next stage (measurement settings).
    6. What decides. A goal makes an objective a limit: here at most 20 ms (objectives).
    7. How much to spend (budget).
    8. Your own settings, handed to every command as the {vars} file.

    Files and loading¶

    • The folder is the loop. Its name is the id: letters, digits, _, -, and . after the first character; at most 60. An id key is refused.
    • The document: problem.yaml (or problem.yml, problem.json). Alternates: NAME.problem.yaml, each with its own results.
    • Beside it: your scripts, library/ (papers, notes), workbench/ (agents' tools and notes), skills/, out/ (results).
    • Parsing: errors give line and column. Unknown keys are refused with a "did you mean" hint.
    • Normal form: equivalent spellings (plan: flux, plan: {by: flux}) share one record.

    Document fields¶

    Field Values / default Purpose
    statement Required non-empty string What to build or optimize
    contract String; empty Interface and rules every design must follow (names, ports, what is forbidden)
    artifact A file name; from the tools, else design.txt The design's file name: its extension is the designs' (below)
    flow Map; defaults below Who does each step: search, generation, checks, measurements, and the supporting boxes
    trunk Map; unset The loop run as a trunk instead of passes, in place of flow with the same contents: Design's by may list agents
    objectives List; empty Limits and ordered preferences (objectives)
    budget Map; defaults below Run length, repairs, concurrency, prototypes (budget)
    vars Map; empty Your own settings, handed to any command as the {vars} JSON file
    skills off, a folder or list of folders, or {from, off}; skills/ Skills (a folder with SKILL.md) the model and agents can load (skills)
    needs Map; unset The default resource hint of every check and stage that says none
    baseline true, false, or a map; absent A reference measured before pass 1 (baseline)

    The design's file¶

    • artifact: a plain file name with an extension (design.py, design.sv, kernel.cu, top.scala); no folder, not hidden. Every design gets that extension.
    • Unsaid: Flux's RTL presets imply design.sv; otherwise design.txt. Say it with your own scripts.
    • language instead names only the language (language: python is design.py). Not both.

    Flow settings¶

    flow says who does each box of the loop's drawing. A box takes a word, an agent's name, or {by: <word or agent>, ...settings, ...agent options}:

    flow:
  design: claude                                # an agent, no options
  choose: {by: claude, session: pass}           # an agent with options
  plan: flux                                    # FluxAgent
  notes: off                                    # a word
    • flux is FluxAgent (Models and agents); model is refused.
    • claude, codex, opencode are built in; a server adds others (**Admin › Runtime › Agents ›
    • Add agent**).
    • {agent: X} is refused: write {by: X}.
    Box Values (first is the default) Purpose
    flow.search.by unset (the rules, no AI), flux, tools, agent Who decides what to try next (given is the rules, under that name)
    flow.search.policy adaptive (default), explore, improve, tune, finetune, variations Sets the search's emphasis
    flow.search.method unset, sweep, montecarlo, anneal, gradient, genetic, pareto, {gradient: {...}}, module:Class, a list of phases How the points of space are picked (search settings)
    flow.search.run A command, with timeout_s (600) Your own search script proposes the points (search command)
    flow.search.scope {list: ..., brief: ..., check: ..., timeout_s: 120} The scopes of one whole design a pass may work on (scope)
    flow.plan off, flux, agent Write the pass's plan, checked before use
    flow.design flux, agent, a list of agents, {run: ...}, {catalog: [paths]} Write each design
    flow.check A command, or an ordered map of named checks; never an agent Decide correctness (checks)
    flow.measure An ordered map of named stages; never an agent Put numbers on passing designs (measurements)
    flow.choose unset (the objectives choose), agent Make the decision; an agent only breaks ties
    flow.notes unset (your notes are read), off Read the notes you send from the loop's Overview (Note to the loop)
    flow.knowledge A map (knowledge): library, by (who digests, or off), insights, ... What the model and agents can look up

    Each key is its box in the configurator's Graph (search is Search, knowledge Knowledge, ...).

    • search: {by, policy, method, space}.
      • by: unset (the rules, no AI), flux, tools (FluxAgent with tools: standings, history, decisions, knowledge), or an agent.
      • method picks the points of space and decides alone. A space with by and no method: by proposes the points.
      • A search word under policy: (or a policy under method:) is refused naming the right key.
      • Shorthand: search: explore is {policy: explore}, search: sweep {method: sweep}, search: claude {by: claude}.
    • search.scope (one whole design, no knobs): each pass works on one scope.
      • list: a command printing the scopes, one per line, name first.
      • brief (given {scope}): what the design agent is told.
      • check (given {scope}, {artifact}): checks the scope after the gate (N failing of M, or its exit). While it fails, the design goes back to the agent, within tries_per_pass.
      • The orchestrator picks direction and scope together, seeing recent scopes and results.
      • For a spec in the folder: list: fluxpreset ndf list --spec {home}/spec, brief: fluxpreset ndf clauses {scope} --spec {home}/spec; fluxpreset ndf scope {scope} --spec {home}/spec lists a unit and its dependents.
    • design, one form:
      • {run: ...}: your script (generator contract); no timeout_s of its own (uses the largest check timeout).
      • {catalog: [a.py, b.py]}: the listed files in turn.
      • flux or an agent. by may list coding agents, taking turns ({by: [claude, {by: codex, model: gpt-5-codex}]}; several Design agents).
      • session: seeded (default; warm start), fresh (also pass), or keep.
    • session: seeded (Design only; default for Claude Code, Codex, OpenCode): one first turn studies the loop in the pass's Setup; each design starts from it (Warm starts). seeded and fresh are refused on other boxes.
      • seed_timeout_s: that turn's limit (default 3600, 300 to 10800): {by: claude, seed_timeout_s: 1800}.
      • reseed_after_bests: redo it after this many new bests (default 7, 0 to 100, 0 never): {by: claude, reseed_after_bests: 3}.
      • Both are refused without the warm start.
    • session: keep (with turns: K, default 8, or turns: forever) on any agent box or critic: kept across passes. Refused on the papers' digester. {by: codex, session: keep, turns: 4}, {by: claude, session: keep, turns: forever}.
    • check and measure never take by:.
    • choose: {by: claude}: an agent breaks ties the objectives cannot.
    • plan is checked before use; a failing plan falls back to the document's order.
    • Thinking: think: true or false beside whoever works a box.
      • FluxAgent (search, plan, design, critics of check/measure/choose, knowledge and its workbench, ideas): {by: flux, think: true} reasons first (slower, often better).
      • An agent (any box, critic or Knowledge section): {by: claude, think: false} runs at its not-thinking effort, true at its thinking effort (the admin's). Refused for a run agent. An agent's effort (agent options) wins over think.
      • Unsaid: the server's thinking by default.
      • {by: tools, think: true} for Search with tools; Search's AI points: search: {by: flux, think: true, effort: high, space: {...}}.
      • Configurator: Thinking (default, on, off) and effort under each chosen agent.
    • Effort (FluxAgent): effort: low | medium | high | max beside by: flux sets thinking, work time and answer length at once; max also checks its own answer. Comes before think. Unsaid: the admin's default.
    flow:
  search: {by: flux, think: true}             # FluxAgent reasons over what to try next
  plan: {by: flux, effort: max}                # works hardest and checks its own plan
  design: {by: codex, think: false}           # the design agent at its effort for not thinking
  choose: {by: claude, effort: high}          # the finer level, as it is
  check: {check: "true", critic: {by: flux, think: true}}         # the critic reasons before it judges
  knowledge: {by: flux, effort: high, ideas: {by: flux, think: false}}   # papers, and the ideas cleanup

    Critics¶

    A critic is a second opinion on one box, said as critic: inside it. Only four boxes take one:

    Box What the critic judges A rejection rounds
    search The direction picked for a pass, before any design work is spent on it The direction is picked again with the objection yes
    check A design the checks passed The design fails; the objection is its note on the record no
    measure A stage's numbers The result is marked rejected and never chosen; it is not measured again no
    choose The pick The decision is made again without it; the critic says whether it rejects the design or the pick yes 
    flow:
  search: {by: claude, critic: flux}
  check:
    correctness: "{python} {home}/check.py {artifact}"
    critic: claude
  choose: {critic: {by: claude, rounds: 2, timeout_s: 600}}
    • A critic is flux, an agent, your own agent ({by: {run: [...]}}), or {by: ..., rounds: N, ...agent options}.
    • rounds (1 to 5, default 1): how many objections the box answers; search and choose only. When they run out, the last pick goes ahead.
    • A search critic needs a picker (by: flux, by: tools, an agent); with the rules, a space, or trunk:, the loader warns. Hand-queued ideas are not judged.
    • A critic that fails or times out has no opinion; it never stops the loop.
    • It runs wherever its box runs: every pass, pass 0, R passes, Re-Evaluate. Numbers already judged are not judged again.
    • The choose critic's rejects: design (final, until Restore in Results) or pick (default; lapses once the numbers change).
    • Its prefers: the design it would choose instead -- only this brings back a design an earlier rejection keeps out (once a decision); designs named in its reasoning do not.
    • Metrics it names in wrong are struck through in Results (values kept).
    • flow.critique is refused (an older key); budget.critique_rounds is ignored with a warning.

    Check settings¶

    flow.check is one command (a check named test) or an ordered map. Checks run in the order written; the first that reports failures refuses the design and the rest do not run.

    check:                                                        # under flow:
  build: "{python} -m py_compile {artifact}"                  # a bare command
  correctness:                                                # or a map
    run: "{python} {home}/check.py {artifact}"
    timeout_s: 60
    Field Default Purpose
    run Required Command string or argument list
    count_re (\d+) failing One capture group holding the number of failures
    fail_re Absent One match per failure; used instead of the default count pattern
    timeout_s 120 Seconds before the check is stopped; a check stopped there refuses the design ("timed out after 120s") and the loop goes on
    needs The loop's needs, else unlimited A resource hint: the cores and GB of memory it uses at most, and the labels of the machine it runs on
    • Names: a letter, then letters, digits, _, -.
    • build: no pattern; any non-zero exit means it did not build.
    • count_re/fail_re directly under flow.check are refused.
    • Output to verdict: check contract.

    Measurement settings¶

    flow.measure is an ordered map of stages, cheapest first. A stage is a command or a map:

    Field Default Purpose
    run Required Command string or argument list (as a check's; command: is refused, as everywhere a document runs a command); {metrics} in it is the stage's metrics, comma-separated (fluxpreset rtl measure {artifact} --metrics {metrics} ...)
    metrics Required unless metrics_re The names printed as name=value -- a number, or a dictionary (below)
    metrics_re Derived from metrics Map of metric name to a regex with one capture group
    needs Inferred for fluxpreset prog count/size; else empty Programs required on PATH; a missing one skips the stage ("NOT RUN"). As a map, also a resource hint: {tools: [yosys], cores: 8, memory: 48}
    timeout_s 600 Seconds before the stage is stopped, with every process it started (a helper it left in the background too)
    cutoff None A gate before the next stage, or a list of gates that must all pass
    estimate Off Predict first, and skip designs the estimate already rules out
    • Non-zero exit: a failed measurement. No numbers; the design is refused there (kept on the record until the document changes or Re-Evaluate); ✗ in Live. Exit 0 with no metric is refused too ("no metric matched in the output").
    • Dictionaries: name={"a": 1, "b": 2} (or in a JSON object) gives name.a, name.b (one test each) and name = their mean.
      • _a sets its aggregate: name={"a": 1, "b": 2, "_a": "sum"} (mean, median, min, max, sum; anything else is refused).
      • Missing, null and non-finite values stay unmeasured, never zero.
      • An objective ranks name (by _a, else the mean), by its own aggregate ({metric: name, aggregate: sum, direction: minimize, unit: us}; wins over _a), or one test ({metric: name.a}). type: is refused.
      • Unranked dictionaries are extra measurements, shown folded in Results.
    • Metric names are unique per stage. evaluator: stages are refused.

    Cutoffs gate the next stage, one rule each: {metric: M, at: N} (at least N), {metric: M, below: N} (at most N), {metric: M, within: F} (within fraction F, 0 < F <= 1, of this run's best there). M may be carried from an earlier stage.

    Estimates: {kind: surrogate|command|model, margin: 0.05}; run only with kind: command (estimate contract). A design estimated past a cutoff or limit by more than the margin is skipped.

    Carried numbers: stages may measure different things. At each stage, a metric's number is its deepest measurement so far; Results says where it came from ("fmax_mhz=500 (from timing)").

    Shared folder: a design's checks and stages in a pass share FLUX_REUSE_DIR, so tools (the presets do) can continue from earlier work. Never shared across designs (Compiling).

    flow:
  measure:
    timing: {run: "{python} {home}/sta.py {artifact}", metrics: [fmax_mhz], cutoff: {metric: fmax_mhz, at: 250}}
    area:   {run: "{python} {home}/area.py {artifact}", metrics: [area_um2]}
objectives:
  - {metric: fmax_mhz, goal: ">= 300"}   # judged on area, with timing's number carried
  - {metric: area_um2, direction: minimize}
    • Every objective needs a stage that measures it. A stage:-pinned limit or a cutoff must name a metric its stage has.
    • task check notes an objective only the last stage measures.
    • Between stages: every design past the cutoffs climbs to the next stage (never measured twice at one stage). Only a cutoff or estimate saves a costly stage; task check says when none does.
    • The decision uses the deepest stage reached. A design that never reached an objective's first stage is not chosen ("stopped at" in Results, or Pending while it may still climb).

    Knowledge settings¶

    Field Default Purpose
    library Empty Files and folders (specs, sources, notes, PDFs), relative to the folder, that join library/ as the loop's library; the AI looks it up when it needs it
    by flux Who summarises the library's papers: flux (FluxAgent) or an agent (its options beside); off turns the library off
    insights {by: off} Conclusions drawn from the loop's results: {by: rules} (computed, no AI), {by: <agent>}, or {by: off}; the agents read them with the library
    workbench who digests Who sums up the agents' workbench/ when it changed: off, flux, or an agent ({by: claude, timeout_s: 600} with its options); unsaid, whoever digests the papers
    ideas flux Who cleans up the ideas notebook before a pass, once it grew: flux (FluxAgent, the default in every loop: no line needed), off, or an agent; {by: flux, open: 20, new: 10} runs it at 20 open ideas with 10 new since the last cleanup (the defaults). It merges repeated ideas (undoable); see Ideas cleanup
    hidden Empty Files, folders or globs (relative to the folder) the AI agents may not read: tests, checks, a gate's files and their parameters; see Hidden from AI
    • Configurator: a bubble each in the Graph's Knowledge group; By off writes off (Library: by: off), Insights' rules {by: rules}. Skills' off is skills: off, Notes' notes: off.
    • by: off allows insights, ideas, workbench, hidden beside it, not library.
    • digest, lessons, off are older keys, refused; sheet, files, text are ignored with a warning.
    • Linked projects' libraries appear read-only at library/<project>@<group>/ (<project>@_ for a global one), in project order, their hidden paths hidden. @ names at the top of library/ are reserved.

    Hidden from AI¶

    flow.knowledge.hidden: paths the loop's agents may not read. Checks, stages and scripts still read them; failure text still reaches the agent.

    flow:
  knowledge:
    hidden: [tests/, golden.py, "params/*.json"]
    • Relative to the loop folder, inside it, never the document.
    • An agent's own hidden: adds paths for it alone.
    • Left out of the library, knowledge files and skills.
    • Not a sandbox: for secrets use the sandbox.
    • Web app: Files › Actions › Hide from AI, or the configurator's Hidden bubble. Chat can still read them to answer you (Hidden from AI).

    Skills¶

    A skill is a folder with a SKILL.md (front matter name and description, then instructions). The loop's skills/ and the built-in flux-loop-commands are used by default (Skills). skills: changes that:

    skills: off                                  # none, not the built-in one either
skills: [skills, ../shared-skills]           # these folders instead of skills/
skills: {off: [flux-loop-commands, rtl-style]}   # skills/ and the built-in one, these two off
skills: {from: [../shared-skills], off: [old-style]}

    Objective settings¶

    Each entry is a metric name or a map:

    Field Default Purpose
    metric Required A metric a stage reports (name or name.test for a dictionary metric)
    direction maximize; a goal written "< 80" or "<= 80" makes it minimize minimize or maximize
    goal None A limit: at most N when minimizing, at least N when maximizing; also ">= 1000", "< 80"
    stage The deepest stage for a goal Where the goal is judged (a stage that has the metric: measured there or carried from an earlier one)
    unit Known for common metrics Display unit
    aggregate mean How a dictionary's tests make its number: mean, median, min, max, sum
    tie 0 Relative band within which two designs tie and the next objective decides
    margin 0 Extra headroom required when a goal is judged on a shallower stage
    balance false Decide by the best trade-off (the knee) of the goal-less objectives
    keep None A relative limit: keep this fraction (0..1] of the best gain over above
    above 0 The reference for keep

    How the decision is made:

    1. A design meeting every limit beats one that misses any. An unmeasured limit counts as missed.
    2. Among those, goal-less objectives decide in written order (within tie, the next decides). With balance, the best trade-off decides.
    3. An exact tie goes to the next objective (limits included), then to the earlier design.
    4. If none meets every limit, the closest (fewest misses, then smallest shortfall) is reported, not decided.
    5. While a stage has refused every design, there is no decision ("None has passed every stage yet").

    goal cannot combine with keep or balance. A dictionary objective ranks its mean unless aggregate (or its _a) says otherwise, or it names a test (d.test).

    Resource hints (needs)¶

    needs: {cores: N, memory: G} (GB) says what a check or stage uses at most. A top-level needs: is the default for every check and stage. Unsaid cores: 1 (its builds run -j1); unsaid memory: unlimited (only the sandbox's memory limit applies).

    needs: {memory: 8}                 # every step of this loop
flow:
  check:
    lint: {run: "{python} {home}/lint.py {artifact}", needs: {cores: 2}}
  measure:
    place:
      run: fluxpreset rtl measure {artifact} --stage place
      metrics: [area_um2]
      needs: {tools: [openroad], cores: 8, memory: 48}
    • Scheduling: the machine's cores and memory (less 10% of memory, at least 4 GB) are one pool for every loop and user. A step (or an agent's probe) starts when its hint fits what is free; else it waits ("waiting for room (needs 8 cores, 48 GB; free 2 cores, 30 GB)"), in fair turns. After 10 minutes, smaller steps no longer overtake it. A step counts the larger of its hint and its stage's peak over the last 20 runs. No cores said: counts 1 core. No memory said: counts none. A step always starts when nothing else runs.
    • Builds: FLUX_JOBS is its cores (capped by the sandbox), else 1: make -j"$FLUX_JOBS". A compile-heavy step that states no cores builds about 2× slower than with the machine's cores, even on an idle machine. To build with more jobs, state needs: {cores: N} on the step, or loop-wide.
    • Not a limit: a step may use more, up to the sandbox's limits. Its loop then gets one note ("Stage place used 37 GB of memory against a hint of 4 GB.") with Set memory: 48 (peak plus a quarter, rounded to 4 GB, 8 GB above 32 GB), which writes needs: {memory: 48} on that stage. Notes come only for what the step says (or for running out of memory).
    • Out of memory: killed because the machine ran out, it runs once more; a second kill fails it. Killed at its sandbox limit, it fails; raise the loop's sandbox memory.
    • Another machine: any other key (fpga: 1, lab: loopback, board: zcu104) sends the step (and its probes) to a joined machine that has it (Machines). Live says where ("… · on runner-1"). true: has the key; a word: exactly that; a number: that many units (fpga: 1 takes one of fpga=2).
    • Other commands: flow.design: {run: ..., needs: {fpga: true}}, the baseline's run, a search's run (flow.search: {run: ..., needs: ...}) and flow.search.scope.needs take labels too; the top-level needs: does not apply to them. by: boxes always run on the server (needs refused).
    • The whole run: flow: {needs: {bigmem: true, memory: 256}} (or trunk: {needs: ...}) picks the machine for the whole loop. Never a step default. Needs the admin's permission; otherwise the loop runs on the server.
    • Never stale: changing cores, memory or labels changes no measurement. Only a stage's tools is part of how it is measured.
    • Configurator: a check's or measurement's Needs row: cores and GB (empty: "unlimited"), then a pill per machine label (+ Add offers your machines' labels, "fpga · 2 machines · up to 2"). A counted label gets a number; another a word. An unknown label (gpu) is kept, dashed ("no machine has this yet"). Save writes needs: {fpga: 1, lab: loopback}. The Preview app offers examples only.
    • Admin › Activity › Resources shows the pool and waiting steps.

    Budget¶

    Run length, repairs, and concurrency¶

    Field Default Purpose
    passes 0 A limit on the passes of a start that asks for none; 0 runs until stopped. A pass is one design, so this is how many designs the start makes, however many run at once; under trunk:, the designs its agents hand in. Counted per start, in both: a restart counts from 0 again. Not in the configurator, and a start from the web never reads it: the Start dialog sets each start's passes, and "until I stop it" means just that
    tries_per_pass 3 What one pass may work through. A loop builds one design a pass, so this caps its tries that give none and a critic's send-backs; for a search, its rounds: a pass carries one proposal, and a round that gives no design takes the next. Leave it out unless a search needs more; only a search's Tries row sets it in the configurator
    repairs_per_design 3 Repairs of one design before it is given up
    designs_at_once 1 Designs at once, wherever: passes at once (each its own design, in its own agent session; passes still counts each; a lane takes the next pass as soon as its own is decided -- with pipeline, as soon as its design is handed in -- and each pass decides as soon as it is measured), trunk branches (twice that may wait), a search pass's designs, the start's re-check's designs. A server limit also applies. Passes of a search run one at a time: the designs at once are inside each pass (what a pass carries)
    tools_at_once auto Tool steps at once across the whole loop: one pool of this many slots. A design's check, its measurements and its decision run as one tool step that holds one slot from its first check to the end of its decision, a wait for other designs' decisions included; on a loop an admin has not allowed parallel work, a design waiting behind a decision that runs an agent turn (a decide by an agent, a select critic) gives its slot back while it waits and takes one again to decide. An agent's probes take slots from the same pool, each probe one slot while it runs (a probe of the gate holds it through all its checks); estimates hold one only while their tool runs. Unsaid: designs_at_once + 1 (a trunk: its branches + 1): a slot per design at once and one spare for an agent's probe; a second probe at once waits for a slot. Use 1 for anything timed, or for a tool that breaks when two of its runs share the machine: no two tools then run at once, checks included. It never holds designs at once, only their tool steps. It is not a share of the cores: each check's and measurement's builds get FLUX_JOBS, its hint's cores, else 1, and the machine's pool keeps every loop's steps within its cores (more slots than cores: the steps past the cores wait for room). A server limit also applies
    agent_continues 3 Times a design agent's work is continued past its time limit before its design is handed in as it stands
    agent_grace_s a quarter of the agent's time limit, 300–600 s A final short turn to get the design past the gate; 0 turns it off
    tools true Whether FluxAgent calls tools inside its turns (compute, check, history, knowledge); false for a server without tool calls. A coding agent's turns are its own
    pipeline false true: drafting the next design overlaps the tool steps of the designs before it -- each lane starts its next design as soon as its current design is handed in by its agent, while that design's check, measurements and decision finish behind it in its tool step -- however long a decision takes (a decide by an agent), the lane drafts on; at most designs_at_once + tools_at_once designs are in flight at once (started and not yet decided: one drafting in each lane, one in or waiting for each tool slot). It never splits a design's check from its measurements. When a design fails its check (or a measurement sends it back to be fixed), its repair is queued on its lane: at the lane's next hand-in the same agent session repairs it, before the lane starts any new design, oldest first, within repairs_per_design, and the design keeps its number. Live's Timeline draws such a repair as its own dashed box on the lane, with its design's tag; the design's page in Results says "repaired after queueing". Each design is decided as soon as it is measured, whatever order the designs started in, and a design refused at a measurement stays a record later passes can improve on. A stop lets the designs behind finish, their queued repairs too, and be decided; Stop now ends a queued repair before it runs, and Results says "check failed; repair queued, not run before the loop stopped" under the design (the next start does not run it: its number stays spent). The next design's agent sees a design behind as being measured, its numbers once they land. No effect on a re-check (it drafts nothing; beside the passes it measures one design at a time, the start's own re-check designs_at_once at once, each one tool step), a search (its pass measures its designs inside it) or a trunk-mode loop (its agents draft while branches run anyway); on a loop an admin has not allowed parallel work (its Settings › Advanced › Allow parallel work) it still pipelines, with one lane, one agent turn and one tool step at a time: the next design's turn runs while the design before it is checked and measured, and Live says parallel work is off in that run. In the configurator: Extra › Running › Pipelining. Live says what it would save on your loop once it has three passes
    • These nine are the whole budget. designs_at_once, tools_at_once and pipeline are type-checked: a whole number of at least 1, a whole number (0 or unsaid: auto), true or false; a document saying otherwise is refused at its check.
    • prototype as a budget key is refused (it is Design's, below).
    • A removed budget key loads with a warning and does nothing (a configurator save drops it).
    • Prototype limits and FluxAgent's tool turns have no key.

    Prototypes¶

    A prototype is the algorithm in Python (or SystemC), checked against the golden model before the target design is written. For problems with a golden model.

    • On Design: design: {prototype: false}, design: {by: claude, prototype: systemc}. Values: true (default), false, python, systemc.
    • With run or catalog: ignored, with a warning.
    • It does not create a golden model.

    Baseline / pass 0¶

    baseline checks and measures a reference before pass 1, so results read relative to it. Off by default. Pass 0 uses no AI, repairs nothing, and does not count toward passes.

    baseline: true                                   # the project as it is: your scripts as written
# baseline: {file: baseline.py}                  # an unchanged design file
# baseline: {run: "{python} {home}/baseline.py {artifact}", timeout_s: 600}
# baseline: {metrics: [{metric: area_um2, value: 120}, {metric: fmax_mhz, value: 1000, stage: place}]}
# add only: true to stop after pass 0
    Form What pass 0 measures
    true Your scripts as written; {artifact} is an empty file, so use {home}/... paths
    {file: F} F (relative to the folder) copied to {artifact}; the original is untouched
    {run: C, timeout_s: 600} Whatever C writes to {artifact} (contract); if it writes nothing, the project as it is
    {metrics: [...]} Nothing runs: the values are recorded as the reference
    • metrics entries: {metric, value, stage}, a finite number; stage defaults to the deepest and must report the metric; each pair once. Never a design or the decision.
    • only: true: stop after pass 0.
    • Reuse: a successful baseline stands while the baseline: section is unchanged. To redo it: Settings › Record › Re-Evaluate with Rerun baseline. A failed one retries at the next start.
    • Baselines skip estimates and cutoffs; they are grey lines and the base of relative values, never the decision or a search start.
