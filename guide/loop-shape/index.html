    Search and agents¶

    Choose what to try next (flow.search) and who makes the design (flow.design). Checks, measurements and objectives stay the same whichever you pick.

    The configurator's Graph draws the loop as a ring. Each box is a key under flow: (or trunk:):

    Box Key Does
    Search search Picks what to try
    Design design Makes it
    Check check Tests it; a failure goes back to Design
    Measure measure Measures it
    Choose choose Decides

    The setup boxes beside the ring run in each pass's Setup, before its design (Setup steps).

    Search a space of settings¶

    List the choices; commands get them as placeholders.

    flow:
  search:
    method: sweep
    space:
      algorithm: [list_sieve, slice_sieve, odd_sieve]
      wheel: [0, 1]
    seeds:
      - {algorithm: list_sieve, wheel: 0}
  design: {run: "{python} {home}/render.py {artifact} {algorithm} {wheel}"}
    • Seeds are measured first. The first seed is the home point.
    • An omitted knob takes its first choice.
    • Order numeric choices: local searches move along that order.
    search How it chooses One pass carries Learns from results
    sweep Every distinct combination Every point (batch_size for fewer) No
    montecarlo Random distinct points batch_size points (8) No
    gradient Coordinate descent over nearby choices A wave of moves (all, or wave) After each pass
    anneal Local moves, sometimes accepting worse One neighbour After each pass
    genetic Selection and mutation A generation, population (8) After each pass
    pareto Trade-offs; needs two objectives Up to wave points After each pass
    by: flux beside the space, no search FluxAgent (or by: claude, an agent) proposes legal points batch_size points (4) After each pass
    control The home point with some incumbent knobs (keep: [...]) One point
    phases Several searches in order The current phase's As that phase
    run Your script: search: {run: "...", timeout_s: 600} (contract) What it prints in one round After each pass
    • Passes (at Start, or budget.passes) count proposals, not points: one sweep pass over 48 points measures 48.
    • budget.tools_at_once: how many of a pass's designs are made and checked at once.
    • With designs at once (pipeline is on unless false), each design is decided as soon as it is measured; a slow or repaired one holds up no other's decision.
    • A finished search does not stop an unlimited run. Cap the passes for a bounded sweep.
    • Designs climb the stages cheapest first; only cutoffs stop a design early (between stages).
    • A re-check (Measure again, a re-evaluation, Evaluate on a probed draft) is a pass of its own between two passes (R, numbered 1.5 after pass 1). It does not count in budget.passes. Asked to measure the baseline again (the Overview's Re-measure of its stale numbers), it runs pass 0 again first.
    • With several designs at once, a draft you Evaluate while passes run does not wait for them: it takes the next free lane like a pass (R 2.5, beside the passes), is checked, measured and decided, and that lane's next pass starts after it.

    A search's options go under its name (search reference):

    flow:
  search:
    method:
      gradient: {steps: 16, patience: 2, reach: adjacent}
    space:
      block: [16, 32, 64, 128]
      order: [ijk, ikj, jki]

    Phases: a list, each {search: ..., <its options>}; policy: sets a phase's emphasis.

    flow:
  search:
    space: {block: [16, 32, 64, 128], order: [ijk, ikj, jki]}
    method:
      - {search: montecarlo, name: sample, samples: 8, seed: 0}
      - {search: gradient, name: tune, knobs: [block], steps: 8, policy: tune}

    Conditional choices and components¶

    A knob that only matters for some choices (inactive knobs stay at home and are not measured again):

    space:
  algorithm: [list_sieve, slice_sieve, odd_sieve]
  wheel: {values: [0, 1], when: {algorithm: [list_sieve]}}

    A component groups knobs; the search sees prefetch.on, prefetch.distance, prefetch.degree, and {point} gives them as nested JSON:

    space:
  prefetch:
    optional: true
    distance: [1, 2, 4]
    degree: [1, 2]

    from: "out/invented/*.sv" beside values adds the files found when the document loads.

    Let a model or agent explore designs¶

    No knob space needed. by says who picks the next direction (unset: the rules), policy the emphasis, design who writes the code:

    flow:
  search: {by: claude, policy: adaptive}
  design: claude
    • policy: adaptive (default), explore, improve, tune, finetune, variations.
    • search: <algorithm> needs a space and decides alone (by has no effect beside it).
    • In the configurator: the Graph's Search box, with Policy, then Parameters (the knobs and Search by: an algorithm, or AI).
    • Only the budget or a manual stop ends an unlimited run; meeting a goal does not.

    Put agents in the right steps¶

    Name an agent; use {by: ..., ...} to add options:

    flow:
  search: {by: claude, policy: adaptive}
  plan: {by: claude, session: keep}
  design: {by: claude, timeout_s: 1800, probe: {gate: 20, stages: 3}}
  choose: {by: claude}
  knowledge: {by: claude, insights: {by: rules}}
    • Built in: claude, codex, opencode. A server can add more.
    • Agents plan, design and advise. flow.check and flow.measure stay commands.
    • The pick still follows the objectives; an agent's advice is checked and can fall back to the rules.
    • FluxAgent: search: {by: flux, policy: adaptive}, design: flux (model is refused). Setup: Models and agents.

    Critics give a second opinion on search, check, measure or choose: critic: flux, an agent, or {by: ..., rounds: N}. A rejection re-picks the direction, fails the design, marks the numbers, or re-makes the pick. Details: critics.

    flow:
  check:
    correctness: "{python} {home}/check.py {artifact}"
    critic: claude
  choose: {critic: {by: flux, rounds: 2}}

    Sessions: a new one each design (repairs included), each pass on other boxes; session: seed or keep says otherwise (Sessions).

    Probes: an agent can run its current file through the gate and stages during a turn. probe budgets them; allow gives back restricted tools (agent options).

    Probed drafts an agent did not hand in are kept as unverified (#p4.1, #p4.2: pass 4, try 1 and 2). They never count. Evaluate (Results) measures one in the next re-check, or, with designs at once, at the next free lane.

    Several Design agents¶

    List coding agents; passes take turns (pass 1 the first, pass 2 the second, and round again):

    flow:
  design:
    by:
      - claude
      - {by: codex, model: gpt-5-codex, effort: high}
      - {by: opencode, model: anthropic/claude-sonnet-4-5}
    timeout_s: 900
    • An entry is a name or {by: <agent>, ...}. model: (or args: [--model, <model>]) sets its model. Design's options apply to all; an entry's own win.
    • The list is the lanes: an entry a lane, lane k drafting with entry k. The same agent twice is two lanes.
    • A design stays with its agent: repairs and continued turns too.
    • Each agent has its own seed and kept sessions.
    • design.prototype is written by the first agent.
    • Refused: an empty list, the same agent with the same options twice, FluxAgent in a list.
    • Live's Timeline and the Agents tab name each turn's agent; Results tags each design's agent once two or more made designs.
    • Configurator: Graph › Design › Add an agent; a tab per agent.

    Sessions¶

    session: on an agent's box (or a critic) says where each turn's conversation starts:

    flow:
  design: {by: claude}                     # none (the default): a new session each design
  design: {by: claude, session: seed}      # each design forks a seed its pass's Setup made
  design: {by: claude, session: seed, every: 5, seed_timeout_s: 1800}
  plan: {by: claude, session: keep}        # one session, kept pass after pass
    • none (default): Design starts a session per design, its repairs going on in it; plan, search, choose and critics one per pass, each critic its own. Paper digests, the workbench and ideas have no session.
    • seed (Design only, Claude Code, Codex and OpenCode): a pass's Setup runs one turn that studies the loop (document, scripts, checks, stages, baseline, best design) and writes notes; each design forks it and is told only its own task and the record.
      • Made again after every passes (default 10, 1 to 1000), and at the next Setup when the document, the agent or its model change, or a file you keep does (the code the checks and stages run, the baseline, the library, the skills; never what a run writes there).
      • seed_timeout_s: its study time, 300 to 10800 s (default 3600).
      • It reads out/ and the workbench but cannot write them (the agent's rules, and Landlock on Linux 5.13+; without Landlock its journal entry says so).
      • A failed seed: designs start from nothing; a Setup an hour later tries again.
      • Live's Setup row says why it runs ("no seed yet", "re-seeding: check.py changed", "re-seeding after 10 passes").
    • keep (any box): one session per design at once, kept pass after pass and never renewed for its turns; a change to the document, agent, model or Flux starts a new one. An agent of your own needs a resume command (agent options).
    • every and seed_timeout_s go with session: seed alone. FluxAgent and run: agents never seed. The Agents tab says how each turn's session began.

    Two ways to run: passes or a trunk¶

    The root key picks the mode. Everything else (checks, stages, objectives, knowledge) is written the same.

    Passes (flow:) Trunk (trunk:)
    Each design Search, Design, Check, Measure, Choose; a failed check is repaired A coding agent hands in one design per turn; branches check, measure and decide it
    Agent session Per pass or per design One for the whole run
    Use for A search over a space, scripts, plans, FluxAgent, steering pass by pass A coding agent that keeps going on its own, one or several 
    trunk:
  design: {by: [claude], timeout_s: 3600}     # a list: one trunk each (one agent is fine)
  check: {...}                                 # as under flow:
  measure: {...}
budget:
  tools_at_once: 3                            # designs evaluated at once (the admin's limit applies)
  passes: 0                                   # designs handed in; 0 = until stopped
    • Trunk: each Design agent keeps one session, resumed at the next start. One turn, one design (at most design.timeout_s). A turn with no design is followed by the next. An agent without resume: starts each design fresh.
    • Branches: up to budget.tools_at_once (the tool slots; unsaid, the trunks + 1) take designs first in, first out, whoever made each (a design a stop sent back goes first). A branch runs Check, Measure and Choose; no Search, Design or repair.
    • Queue: at most the trunks plus the slots are handed in and not decided (waiting or running). Lowering either keeps what already waits.
    • Ideas: each turn is told the queued idea, else the best unmeasured one (ideas: {suggest: false} turns that off). A design names the idea it tests.
    • Notes to the loop reach each agent every turn while they stand.
    • Search is off by default. search: flux or an agent adds a bud every 10 decided designs that writes up to 5 new ideas, within its agent's time limit (search: {by: claude, timeout_s: 1800}; unset, the agent's own; FluxAgent 15 minutes). A repeated idea shows proposed again ×N; the count changes nothing. The run's log says at its start whether Search buds run and why not when off (Search buds: off -- Search is the rules; ...), and when the next is due (Search buds: on -- one every 10 decided designs (Search: claude); the next when 30 are decided (24 now, ...)).
    • Ideas cleanup (knowledge.ideas) runs in a setup bud once the notebook grows; the cleanups that follow a productive one run in the same bud, one after the other.
    • Repairs are the agent's own; repairs_per_design does nothing.
    • Setup runs once at start, with no paper summaries, workbench README or ideas cleanup: the start's first setup bud runs those beside the trunks. Run setup on Live or a library change runs a bud again.
    • Start: the baseline if asked, then the re-check, then Setup and the trunks.
    • Refused: a space or search, plan, a Design not by a coding agent, both flow: and trunk:, design: {session: trunk} under flow:.
    • design.prototype does not run; Check warns.
    • Several agents: each is a trunk (t1, t2, ...). The same agent twice with different models is two trunks:
    trunk:
  design: {by: [claude, {by: claude, model: opus}, codex], timeout_s: 3600}

    One loop, one design¶

    A loop answers one problem with one design. Several blocks of one IP are one design under one top module (as the bundled nlu). Several problems are several loops; a chart can compare them.
