    Knowledge, skills, hidden paths¶

    What the loop's model and agents can read besides the document, and what they may not. Fields: Document reference › Knowledge.

    Files, notes and papers¶

    flow:
  knowledge:
    library: [spec.md, reference.py, notes/]
    by: claude
    insights: {by: rules}
    Key Does
    library Files and folders added to the loop's library/ (a folder counts as each of its files)
    by Who summarises the papers: flux (FluxAgent, default) or an agent; off turns all reading off
    insights {by: rules}: facts from the results, no AI; {by: <agent>}: conclusions citing designs; unset or {by: off}: none
    • Agents read the library on demand, in pieces. Nothing is pasted into prompts. Hidden paths never appear.
    • Papers are summarised in each pass's Setup, before its design. An unsummarised paper is read whole.
    • You read the library, its digests and outlines in Files › Library. The agents read the insights with it.
    • A linked project adds its library read-only at library/<project>@<group>/, while the loop's owner is a member.

    A project's knowledge (web app, the project's Knowledge tab): one insight per entry, each under a topic and proven by designs, added by hand or proposed by the collector.

    • A linked loop's agents read accepted entries with the library (pinned first), as they stood at its start.
    • Each accepted entry becomes an idea in every linked loop's notebook ("from silicon@hw-lab"), scored like any other. A global project's entries need the link's learning on.
    • A retired entry's idea is marked for deletion.
    • More: Groups › Knowledge.

    Tip: a model that keeps getting it wrong usually lacks a fact. A method note (the method and the facts, not a design) helps more than more passes.

    How agents read the library¶

    The library (the loop's and its projects') is read in pieces, never pasted whole: a list of every document (name, pages or lines, what it is) and each linked project's topics; a search returning the nearest files with their digests and best passages; a document's digest, its outline, one section, the passages around a phrase, or a range of lines or pages; one project entry; the insights so far.

    • Names: the path in library/ (booth.md, papers/x.pdf, silicon@hw-lab/x.pdf).
    • Outline: from headings (Markdown #, LaTeX \section, PDF numbered and usual headings); else by page, or 120-line chunks. Files › Library shows the same outline and digest.
    • Formats: text; PDF; Word, Excel, PowerPoint, OpenDocument, HTML and EPUB as Markdown-like text.
    • Title: an HTML <title> or EPUB title, else the file name.
    • Hidden paths are refused.

    Skills¶

    A skill is a folder with a SKILL.md (front matter name and description, then instructions) and its files. Skills in the loop's skills/ folder are used automatically by the model and every coding agent. The built-in flux-loop-commands skill comes with them.

    skills: [skills, ../shared-skills]           # these folders instead of skills/
skills: {"off": [flux-loop-commands]}        # skills/ and the built-in one, this one off
skills: "off"                                # none at all
    • In the web app: the configurator's Knowledge Skills bubble (Settings › Problem › Configurator › Graph) turns skills on or off and lists them.
    • A project's skills (its Skills tab) reach linked loops at skills/<name>@<group>/, read-only, after the loop's own. Turn them off the same way.

    Hidden from AI¶

    An agent that can read the tests can write a design that passes only them. knowledge.hidden hides paths from the loop's agents:

    flow:
  knowledge:
    hidden: [tests/, golden.py, "params/*.json"]
    • Checks, measurements and scripts still read them; a check's failure text still reaches the agent.
    • Paths are relative to the loop folder. An agent's own hidden: adds paths for that agent.
    • Not a security boundary: for secrets, use the sandbox.
    • Chat can read hidden files to answer you; the loop's agents cannot.

    Hide a path in the web app:

    • Files: a file's Actions › Hide from AI;
    • configurator Graph: the Knowledge group's Hidden bubble;
    • New loop › Agent: Hide from AI on a file.

    A hidden path shows a lock before its name. Point at it to see hidden from AI or the pattern that hides it.

    Ideas cleanup¶

    The ideas notebook holds each hypothesis and the designs that tested it. knowledge.ideas says who merges duplicates, in a pass's Setup. Default: FluxAgent.

    flow:
  knowledge:
    insights: {by: rules}
    ideas: claude                        # an agent; or {by: flux, open: 30, new: 15, timeout_s: 300}; or off
    • When: in a pass's Setup, at most one cleanup each (under trunk:, in a setup bud beside the designs, never before the first one), once there are open open ideas (default 20) and new new or updated ones (default 10) and 5 designs were tried since the last cleanup; also, at open ideas, at the first cleanup after a start and again right after a cleanup that merged or marked an idea (in the next pass's Setup; under trunk:, at once in the same setup bud, after a Search bud that came due meanwhile), for as long as each one changes something. The log says what the next waits for (ideas cleanup: changed nothing -- the next waits for 10 new or changed ideas and 5 designs tried); Live shows Setup · ideas with why it waits.
    • How much: 60 ideas per cleanup, new ones first, then those looked at longest ago; a growing notebook gets more cleanups, not bigger ones. The log shows progress (ideas cleanup: 60 of 650 not yet reviewed). Under trunk:, Run setup cleans the rest.
    • How long: one cleanup works 5 minutes at most (timeout_s; an agent's own timeout_s is its limit). Then it stops: its merges stay, the rest waits for the next cleanup, which has half as many ideas (ideas cleanup: cut at its time limit ...).
    • What: merges ideas that say the same thing (nothing is deleted; evidence moves to the kept idea); may set a new idea's priority; may mark an unusable idea for deletion, saying which kind: off the problem, self-contradictory, against a constraint, empty or garbled (never a tried, queued or near-duplicate one).
    • Suggestion: with nothing queued, a pass may take the best unmeasured idea (Live: suggested idea). ideas: {suggest: false} turns this off.
    • See merges: Results › Ideas folds merged ideas under the kept one (×N). "idea 7" is an idea; "#7" is a design.
    • Delete: the bin in Results › Ideas; Undo restores it.
    • Marked for deletion: a person accepts or rejects the mark in Results › Ideas.
    • Turn it off: ideas: off (or {by: off}). Web app: the Graph's Knowledge Ideas bubble.

    Workbench¶

    workbench/ is the agents' own folder: tools and notes, shared by the loop's agents, kept across runs.

    • knowledge.workbench: who summarises it into README.md (off, flux, or an agent; default: the paper summariser).
    • The README is rewritten in a pass's Setup when the workbench changed.
    • Web app: Files › Workbench. The library: Files › Library.

    Setup steps¶

    Each pass runs three steps in its Setup, before its design:

    Step Key Runs
    Paper summaries knowledge.by While papers are new (8 a pass)
    Workbench README knowledge.workbench When the workbench changed
    Ideas cleanup knowledge.ideas Past the thresholds; one at most a pass, 5 minutes at most

    A step whose papers or workbench files did not change since it last ran is skipped.

    • Passes at once take each step one at a time; the next finds what the one before wrote.
    • With pipeline, the next pass's Setup runs while the last design is checked and measured.
    • Live's Timeline shows them on the Setup row as the pass's Setup. Under trunk: they are setup buds: the first bud of a start runs the papers, the README and the cleanup beside the first designs, so those read the previous README and summaries (none on a first start).
