    Tour¶

    Flux is a shared server with accounts, used in the browser. Each user has loops; each loop is a document and its files, run sandboxed on the server. Create, check, start, stop, follow and read loops here. Install starts a server.

    Try it first in the Preview app: create a loop step by step, then a tour of the app, or the tour alone.

    Loops¶

    The first page lists your loops. Each row shows:

    • its state, and its design agent (who works its Design box; tinted while running);
    • its designs as "2 / 12 / 30": accepted this start / accepted / all (every design handed in); the tooltip says accepted of measured (accepted and rejected), failed and pending. The Overview's Acceptance rate is accepted ÷ measured;
    • the decision's main measurements (Settings › Measurements' Main, else the first objective), green or red against their limits;
    • Start, Stop and Restart as small icons at the row's end.

    Search, filter by state, sort by activity, name or decision. Shared with me lists loops shared with you or your group, with your rights ("ask · edit · run"). Archived loops are under Archived (Archive).

    Project tabs: when you see a group's project, tabs above the search filter by project: All, one per project, In no project, each with a count. Under All, a Project column names each loop's first project and "+N" others (Groups). The chosen tab is remembered in this browser.

    New loop¶

    Way What it does
    Configurator A form in six steps (Create a loop in the Preview walks through it)
    Create or upload An empty loop, or one from a folder, files, a .zip, or a pasted document (Paste YAML)
    Direct edit Write the YAML yourself
    Agent An agent writes it from your prompt and files (Write a loop with an agent)
    Clone A copy of a loop's problem, without its runs

    A loop's page¶

    The header has Start (▶) at rest, Stop (■) and Restart (↻) while running.

    Tab What it shows
    Overview State, decision and objectives, best designs, best-so-far chart, notes, the agent's questions
    Live The run now and every pass, as a graph or timeline (Live)
    Results Every design measured, charts, ideas, library (Results)
    Agents Every model and agent turn, newest first: where (pass, box, try), outcome, prompt, reply, tool calls, time, tokens; session info ("resumed (turn k of K)", "new session", "warm start", "shared first session")
    Files The loop's files and the agents' workbench (Files and settings)
    Settings Preferences, sharing, maintenance, the problem (Files and settings)

    An agent writing or revising the problem shows a strip at the top of the Overview until the loop starts, the document changes, or six hours pass. Hide from Overview hides an ended strip. Its history: Settings › Problem › Agent.

    A loop that lives in VS Code (VS Code) has a VS Code tag beside its name in the list, and VS Code · on its page; hover the tag to see when the machine was last heard. Its runs go to that machine, so Start waits while the machine is not heard. Its files are read-only here: what would change them (editing the document, Add, Import, Reset, Archive) is turned off, with the reason. Change them in VS Code, or Take back the loop in Settings › Name & ownership. Rename still works here, and VS Code follows it.

    Overview cards¶

    • Decision: the decision and its pill (✓ accepted; ! closest when nothing meets every requirement; ✗ failed), "ties with #229", "last pass 17 min ago". Hover the pill for the rule ("Decided by: smallest area_um2 at fmax_mhz >= 1000") and stage. Below: a tile per main measurement with its change from the reference, then Best 3.
      • The reference: the latest baseline at its stage, else the accepted designs' P10 (minimized) or P90 (maximized). Every page compares with the same reference.
    • Best: a chart per main measurement, titled "best cycles (-12.9%)" (or "best cycles 6189" without a baseline).
    • Starred designs (add it yourself): a tile per starred design, latest first.
    • Note to the loop and Agent asks: below.
    • Small cards (top row): State, Designs measured, Passes, Last improvement, Working now by default; up to 10.
    Small card Shows
    Passes The loop's passes over every start, as its record counts them; while it runs, this start's too
    Last improvement When the best design last improved ("42 min ago"), which design, which pass, passes since
    Pass speed Median wall time of the last 20 passes, most at once, passes per hour
    Working now Agents and models at work, designs per box ("11 design · 3 check · 2 measure"); "idle" at rest
    Idea queue Ideas queued, evaluated, and proposed but neither
    Uptime How long this start has run; starts today
    One metric One metric's best accepted value and change from the baseline ("−12.9%"); the metric you type in the layout editor, else the first objective
    Stage funnel Designs made → passed checks → measured on the last stage

    Customize cards in Account › Profile › Customize (Overview layout); Defaults restores them. Hidden cards cost nothing to load.

    Start, stop, restart¶

    Start asks how many passes (one design each) or Until stopped.

    • A trunk asks for designs and says what runs ("trunk: 2 agents (claude (opus), codex), 3 evaluated at once, 5 handed in at most, pipelined").
    • A folder with several problems asks which; one that does not load is shown with why and a Direct edit link.
    • It checks the document first when inputs changed (as Settings › Problem › Check); on failure the button reads Start anyway.
    • A start resumes from the record. Started from the Loops list, you stay on the list (Started, with Open).
    • A failed loop shows Start again. While an agent writes the problem, Start waits.

    Stop and Restart act after the current pass. The asked button turns red with an hourglass, an amber pill shows "Stops after pass 4" or "Restarts after pass 4", and the loop stays running until then. Press the other to switch. Press the same one again (it turns solid red) to act now: it asks, then abandons the pass.

    A loop's Chat¶

    Chat, on every tab of a loop, opens a panel with one conversation about the loop.

    • The bar: the conversation's name (opens the list, with + New chat and Delete), Open in Chat (opens it in the top bar's Chat), Close.
    • Ask puts a question (why it stalls, which design is best, what to try) to an agent or FluxAgent. It reads the loop and changes nothing.
    • Thinking & commands under an answer shows how it was made.
    • Enter sends, Shift+Enter adds a line.
    • A dot on Chat means the loop's agent is asking you something.
    • The loop's chats share a Chat workbench (editors only), separate from the loop's own workbench/ (A loop's Chat workbench).
    • Old #/app/NAME/ask and #/app/NAME/talk links open it; #/app/NAME/chat/ID opens one conversation.

    Note to the loop (Overview card): a note sent while the loop runs reaches its agents at the next step (a trunk: each agent's next turn), and every step while it stands.

    • Enter sends. A loop at rest has no box.
    • Notes are listed newest first. A filled dot: read ("Read at pass 14"); a ring: waiting.
    • The latest three show; N more shows up to twenty.
    • Editors remove a note with its bin. An unread note then never arrives; a read one leaves the agents' next messages.

    Agent asks (Overview card): the agent's question with its choices, You decide and a free answer; your answer goes as a note. Answered questions are listed below. Hidden when there is nothing.

    The question's line above the tabs, and the bell, lead there. With the card hidden, Answer opens a dialog.

    Chat in the top bar is the same, bound to no loop (Chat); its rail lists your loops' conversations (Loop chats).

    Everywhere¶

    • Top bar: Chat · Loops · Groups · Admin (admins). New loop is at the end of the Loops list's search bar.
    • Theme: system, light or dark; remembered in this browser.
    • Your name opens Account. While an admin views as a user, it shows that user's name.
    • Bell: a run ends or fails, an agent asks, a loop is shared with you.
    • Browser tab: names what is open ("cpu_tune — Loop", "CPU block diagram — Chat"). Its icon's dot: pink something waits for you, red failed, blue running or answering.
    • Live updates: pages refresh only what changed, keeping your scroll and selection. An editor you are typing in is never replaced: Changed on the server offers Reload. A background tab pauses and catches up when you return.
    • Long lists load more as you scroll ("N of M").
    • Raw and Fullscreen on files, logs, results and agent turns.
    • Addresses name the view: #/app/NAME/live/timeline, #/app/NAME/settings/problem?step=graph.
    • Phone: account items move to the menu button; lists and tabs stack.

    The Preview app runs these pages on sample data.
