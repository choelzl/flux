    Chat¶

    Chat (top bar) is a conversation with an agent or FluxAgent, bound to no loop. Ask about your loops, a paper, an idea; have it write a script or keep notes. Available when an admin enables it (Admin › Runtime › Chat).

    The page¶

    The rail (left) lists chats; the conversation is in the middle; Settings (the sliders, top right) opens on the right.

    Rail tabs: Chats (yours), Loops (Loop chats), Projects (Project chats), then + and Close. Arrow keys, Home and End move between tabs. A tab with a question waiting shows a dot.

    • + starts a chat where you are: your own, or on the open loop or project.
    • Chats: a Search box, then Pinned, Today, This week, Earlier. A spinner marks a chat being answered; a dot marks one asking you (the top bar's Chat too).
    • A chat's more menu (three dots): Pin / Unpin (yours alone), Rename, Delete (removes messages and answers; the workbench stays).
    • Close hides the rail; the menu button brings it back.

    Your messages are on the right, answers below. Under each answer: the agent, how long it took, and Thinking & commands (the terminal icon). Files the answer wrote are listed under it (↳ designs/adder8_csel4.sv); click to open.

    The message box:

    • Enter sends (also Ctrl+Enter, ⌘+Enter); Shift+Enter adds a line.
    • Pick the agent inside the box (agents offered for Ask, with your settings: Models and agents). A ! means it is not ready: click for Test and Set up.
    • Think: a slower, more considered answer. Each agent starts as the admin set it (thinking by default); your browser remembers your choice per agent.
    • Effort (with Think on, for coding agents): Claude Code low to max, Codex none to xhigh, OpenCode minimal to max; default is its thinking effort. FluxAgent's Effort (low to max) shows always.
    • One answer at a time per chat. The row shows Sending…, Starting…, Starting OpenCode…, then the agent's current command, with Stop.
    • A stopped answer is kept, marked Stopped before it ended. A failed one says why with Retry.
    • Opening a chat picks the agent of its last answer.
    • Answers run in your own sandbox, kept warm between messages (the admin sets how long). An answer interrupted by a settings change or update restarts (restarted: …).
    • Coding agents have time and tool-call limits set by the admin.

    Attached files¶

    Attach with the paperclip, by dropping on the conversation, or by pasting (a screenshot becomes pasted--.png).

    • Each uploads at once as a chip above the box (Remove takes it off) and goes with your next message.
    • Limits: 50 MB per file, 10 per message, unless the admin changes them.
    • Kept in the workbench's uploads/ (workbench on), else in the answer's attached/. Names never overwrite (notes (2).md).
    • Coding agents open any file with their own tools. FluxAgent reads text, PDF, Word, Excel, PowerPoint and OpenDocument, not pictures.
    • In a loop's Chat: editors' files go to the Chat workbench's uploads/; others' stay with the answer. Never in the loop's own folders.

    Pictures, diagrams and charts¶

    Answers are Markdown. Code blocks have Copy; a block opened with four backticks or ~~~ can hold ``` fences.

    • Pictures: ![caption](/workbench/plots/speed.png), or library/... in a loop or project chat. PNG, JPEG, GIF, WebP and SVG. Click to open the viewer (wheel or pinch to zoom, drag to move, Fit or 0, Esc to close). Anything else (web addresses, data:, paths outside the workbench or library) stays as text.
    • **``svg**: drawn in the page's colours. Classes:box,edge,label, tonesink,muted,line,surface,accent,ok,warn,bad, tintsbox tint-1tobox tint-6`.
    • **``figure**: HTML cards and containers for drawings no diagram kind fits. Root
    • ```diagram: a short YAML that names parts and picks a kind; Flux lays it out.
    • ```chart: JSON; drawn like Results' charts.
    • Save to the workbench writes a drawing as plots/<name>.svg (a diagram's YAML beside it as plots/<name>.diagram.yaml).
    • Nothing an agent wrote runs: drawings are shown as images.
    • Without the Internals permission, svg, figure and diagram blocks arrive as finished pictures (Fullscreen and Save image only, no source). Charts are the same for everyone.
    • ```mermaid is no longer drawn: old answers show it as code to admins, a note to others.

    Diagram kinds:

    Kind Draws
    pipeline Stages in columns, pipeline registers between, back edges in lanes below
    cycle Equal steps in a row, back edges below, an optional band
    architecture Rows of cards and groups (name, muted line, icon)
    layers Stacked bands; a bus joins every box beside it
    blocks Free composition: boxes, stores, states, start/end dots, buses, nested groups; state machines and flow charts (@decision diamonds)
    timing Waveforms: one word a cycle (0 1 . x A0 z), phases, edge arrows (valid@2 -> ready@4: handshake), skipped cycles (~12), gated clock (c); also week plans
    memory A memory map, highest address on top, holes shown, nested regions
    sequence Participants, lifelines, messages, dotted replies, alt and loop frames

    matrix A table of cells (a cache's sets by ways, a reservation table)
    panels Up to four drawings on one image, a chart among them
    sankey Flows From -> To: amount; percent: source or percent: total adds shares
    • In blocks, edges place things ("A -> B"); place: lines add the rest ("Registers under Execute"). Ports (Adder.a), bundles (A, B -> X, Y), layout: ring.
    • Ranges name many parts (R00..R33). Edge widths: @wide, @narrow. legend: explains tones.
    • Roles tint parts: @compute, @storage, @interconnect, @io, @control, @external; @accent highlights.

    • Flux sizes and routes everything so nothing overlaps and it fits the column. A label with no room becomes a number with a key. Too wide: it reflows, else is drawn wider and fitted.
    • A block with mistakes shows its errors instead ("edge 3: unknown box 'Excute' (did you mean Execute?)"), and Ask to fix drafts a fix request.
    • Before you see an answer, Flux sends a broken diagram back to the agent, up to 5 times (Diagram tries in Admin › Runtime › Chat; 0 turns it off). The row says Fixing the diagram (2 of 5)…. After the last try: Flux sent this diagram back to be fixed 5 times; it still does not draw. One that reads badly is sent back once more.

    Charts:

    {"type": "scatter", "title": "Area against fmax",
 "x": {"label": "MHz"}, "y": {"label": "um2", "log": false},
 "series": [{"name": "sweep", "points": [[800, 30], [1200, 18]]},
            {"loop": "bob/mul8", "x": "fmax_mhz", "y": "area_um2"}]}
    • type: line (default), scatter, bar (x may be a category).
    • An axis may say "better": "lower" (or "higher"): best-so-far step line, or dashed fronts. "goal": 2 draws a dashed line ("≤ 2").
    • Point tags: ["4 @failed", 2.3] hollow, @decision orange ring, @accent, @ok, @warn, @bad ring it.
    • A loop series: loop (owner/loop), y a metric, x design (default) or a metric; optional stage, part. Read live with your rights, drawn as Results draws it. Click a point for Open in Results. An unreadable loop says "owner/loop: not available".
    • Limits: 8 series, 500 points per written series, a loop's newest 5000 designs.
    • Show the source, Copy, Fullscreen, Zoom to an area.
    • An invalid block stays as code with why ("Not a chart: colour is no field of a chart.").

    Loop chats¶

    The Loops tab lists each loop you can read that has conversations, latest first (loops you may ask about with none yet come after, greyed). Find a loop or a chat filters.

    • Click a loop: ‹ goes back; its conversations are listed like Chats; + starts one.
    • A conversation opens with the loop's name as a tag. It works like a chat, answered by the loop's own Chat: one answer at a time per loop (One answer at a time per loop), reads the loop, changes nothing itself: it proposes changes to that loop alone (every kind but Library: a document goes under library/ as a Document), for you to accept.
    • Only people with Ask on the loop can ask; others can read. A private conversation (asked by someone without edit) is shown only to its asker.
    • The answer runs on a machine, never on the server. The head says which (on machine); with none, no machine and nothing is sent until one is added (Machines). It runs as the loop's owner, with the owner's agents, on the owner's machines too, for anyone with Ask.
    • A loop that lives on a machine in VS Code is answered there, in its folder, by the agents its problem.yaml defines and FluxAgent.
    • Files attached to a question and the Chat workbench go with it to its machine; what the agent writes in the workbench comes back.
    • Settings shows the loop (read-only) and, for editors, its Chat workbench.
    • Open in NAME opens the loop's page on that conversation.
    • more: Pin; Delete for editors and for a private conversation's asker. No Rename (the title is the first question).

    Project chats¶

    A project's own members read its conversations; those who may edit, curate or manage it ask. Someone who sees it only through its group sees none (Groups). The project's Chat button opens one.

    • The Projects tab works like Loops. Inside a project a line shows 12 entries · To review: 3 · 4 loops.
    • The agent reads the project read-only: library, accepted knowledge, topics, and its loops you may ask about. Hidden paths stay hidden. Your own model settings, base network, no web tools; one answer at a time per project.
    • Proposals (Actions): Knowledge (an entry to To review, never straight in), Topic, Library (files from the project's Chat workbench).
    • The project's Chat workbench works like a loop's. An archived project's chats are read-only.

    Questions¶

    An agent asks only when it cannot go on without you. The question ends the answer as a card.

    • Up to four questions; chips at the top move between them (✓ Type · Widths · Target, 2 of 3).
    • Each has options (one marked Recommended), value fields, and Other for free text.
    • 1–8 pick, Enter moves on, Next › and Back too. Send once something is answered; blank questions are the agent's to decide.
    • You decide lets the agent choose all.
    • Typing a normal message also answers.

    The answer goes as one message to the agent that asked:

    Answer to: Which adder families should adder16's generator try?
- choice: carry-select
- choice: Kogge-Stone

Answer to: Which cell library?
- choice: sky130
keep it small

    Actions¶

    Agents never change your loops themselves; they propose. Each proposal is a card: what, where, why, a preview. Accept makes it as you (same checks and audit as by hand); Reject drops it. The card then says Done, Rejected or Refused with why.

    Kind What it does Its preview
    Library copies files from your workbench into the loop's library/ (papers, notes its agents read) each file, its size and where it goes; replaces when it overwrites one
    Document writes a text file (.md, .txt, .rst) under the loop's library/, where its agents read it; a lesson (what a run taught) goes under library/lessons/ the text, or the change to the file it replaces
    Note sends a note to the running loop, as the Overview's Note to the loop does the note
    Hidden from AI hides paths from the loop's agents, or shows them again (Hidden from AI) the hidden paths before and after: each still hidden with its lock, one shown again struck through
    Idea adds an idea to the loop's notebook its title, hypothesis and test
    Queue queues an idea for testing, or takes it off the queue the idea and its place in line
    Merge merges ideas that say the same thing, as the notebook's cleanup does (it can be undone) the idea kept and those merged into it
    Design note pins a note on a design, shown in Results' design detail and in Live's inspector the design, its numbers, the note
    Reference marks a design as a reference for comparison the design and its numbers
    Settings changes settings of the loop's problem document -- its budget, who works a box, its model, anything the Configure page sets -- saved as the Configure page saves each setting now and proposed; when it takes effect
    Problem document replaces the text of the loop's problem document (its flow, checks, measurements), saved as Direct edit saves the change, line by line; when it takes effect
    Measure again measures a design again (a flaky timeout, a tool that failed), as Results' Reject with Measure again does the design, its numbers, the stages, and when it is measured
    • Design notes and references are for reading only.
    • Settings and Problem document reach a running loop at its next start (Restart). They must still load; a document changed since is refused on Accept. Saving settings drops comments.
    • A design to measure again counts as rejected until measured.
    • Files the agent brings (a downloaded paper) go to your workbench first.
    • A proposal copying a file the loop hides from its agents is refused, naming the file.
    • Checked when the answer ends and again on Accept: you must own the loop or have Edit; not archived. At most 10 proposals per answer.
    • A loop that lives on your machine in VS Code keeps its files there: a change to them (Document, Settings, Problem document) is accepted in its Flux tab in VS Code, which writes it in your folder; here the card says so and offers Reject. Once accepted there it says Done · applied on your machine, and the server's copy follows your folder as you save, so the next proposal is made on what you have. Chat's own page cannot make such a change.

    Settings¶

    The panel's Uses:

    Switch On
    Loops The agent may read your loops: your own, and those shared with you with Ask. The line says how many.
    Workbench The agent may read and write your workbench.
    Network The agent may reach the hosts the admin allows for chat, or any host when the admin opens it. Off, it has the sandbox's base allowlist only, which agents need to work. The line says which. On, FluxAgent also has its web tools.
    • A new chat: Workbench on, Loops and Network off. Make these my defaults changes that. A switch the admin keeps off is greyed with why.
    • Each answer uses the switches as they were when sent.
    • Workbench is shown only with the Internals permission; for others it is on, unseen.
    • In focus (with Loops): one loop the answers look at closely.
    • A loop's chat has no switches: its loop read-only, base network, no web tools.
    • The panel remembers open or closed. Under ~1360 px it opens over the conversation.

    On the web¶

    With Network on, FluxAgent has web tools:

    Tool What it does
    Fetch Gets a page or a document over HTTP or HTTPS and reads its text: HTML, PDF, EPUB, Office files, plain text. A PDF or other document is saved whole.
    Paper search Searches arXiv and OpenAlex. Each paper comes with its title, authors, year, venue, the start of its abstract, its DOI and an open-access PDF's address when known.
    Web search Searches the web, only when the admin set a search provider (Admin › Runtime › Chat).
    • Only hosts the admin allows (or any public host); never private addresses. Paper search needs export.arxiv.org and api.openalex.org.
    • Saved files go to the workbench's uploads/ (never overwritten: paper-2.pdf). To add one to a loop's library, the agent proposes it.
    • Only search words go out, never your data. The answer cites addresses.
    • Thinking & commands shows each fetch; the audit records hosts.
    • Coding agents use their own web tools within the chat's network.

    The workbench¶

    One folder for all your chats: tools/, notes/, drafts/, uploads/. Chat does not create or run loops; drafts for one wait in drafts/ (start a loop from New loop).

    • Settings › Workbench shows a tree. Files open read-only with Download, Delete, Fullscreen. Refresh reloads (also after each answer).
    • Each answer lists the files it wrote. One another chat may have written meanwhile is dimmed, changed meanwhile.
    • A path an answer names (/workbench/notes/speed.md, notes/speed.md) becomes a link if the file exists.

    A loop's Chat workbench¶

    A loop's chats share one Chat workbench, separate from the loop's own workbench/ (the loop's runs never see it).

    • For editors only (owner, Edit, admins) with the admin's Workbench allowed. Others' answers get none, and their attached files stay with the answer.
    • Without the Internals permission there is no tree to browse, but answers still use it.
    • It moves, is renamed and is deleted with the loop; deleting a conversation or resetting the loop keeps it.
    • A project's Chat workbench is the same, kept apart from its library and knowledge.

    Share¶

    Share (first tool of a conversation's head) makes a read-only link.

    • What it shows: the whole conversation, or one answer.
    • Who can open it: signed in to this Flux, or anyone with the link.
    • Expires: 1, 7 (default), 30 or 90 days; never only for signed-in links. Anyone-links last at most the admin's limit (90 days unless Admin › Runtime › Chat › Sharing says less).
    • Make link, Copy, Revoke. Account › Shared links lists all.

    The page is live: it shows answers written after the link was made. Workbench pictures in answers are shown; other workbench and attached files appear by name, not shared. Never shared: workbench, attachments, Thinking & commands, proposals, the loop, library, settings.

    • A loop's conversation needs the Share right; the link shows only your questions ("1 question of another person is not shared").
    • A conversation quoting a file hidden from the loop's agents is not shared.
    • A broken link (revoked, expired, deleted, right lost) shows This link does not open. A signed-in link without a session goes through sign-in.
    • Search engines are asked not to index it.
