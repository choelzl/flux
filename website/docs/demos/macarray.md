# MAC array

**The MAC processing element's microarchitecture, on real ASAP7 numbers.** The array is given
-- `lanes` products summed per cycle at the precision the workload declares (int8 by
default). What is searched is inside the PE:

| knob | values | what it changes |
|---|---|---|
| multiplier | behavioral, shift-and-add, radix-4 Booth, Wallace tree, plus anything a model invented | how each product is formed |
| reducer | chain, tree, carry-save | how the products become one sum |
| pipeline | 0-3 | register stages: products, output, a cut through the reduction |

48 points. Every one is generated by code, **verified by Verilator** against golden vectors
seeded from the workload (with its latency checked against the stages it claims), **screened**
by Yosys + OpenSTA (seconds, optimistic, identical in method for every candidate), and the
finalists spread along the fmax-vs-area frontier are **placed by OpenROAD** -- the only stage a
report may quote.

```bash
cd flux
nix develop --command flux task run applications/macarray/macarray.problem.yaml --passes 1 --steps 1   # screen + placement, no model
nix develop --command flux task run applications/macarray/macarray.problem.yaml --passes 1 --steps 1 --screen-only
nix develop --command flux task run applications/macarray/macarray.problem.yaml   # invention rounds, until `flux stop`
```

The decision is the **smallest PE that makes the target clock**. The frontier is printed whole
-- each row faster than everything smaller, saying what its extra area bought -- so a reader
with a different clock picks their own point. The record (`applications/macarray/out/macarray.db`
by default, or `--db`) keeps every measurement keyed by tool fingerprints and exact source; a
resumed run re-measures nothing.

## Changing the ask

The knobs are the document's `params:`, not command-line flags. For 16 lanes at 1.5 GHz, copy
`macarray.problem.yaml`, set `params.lanes: 16` and `params.target_mhz: 1500` (and the
`fmax_mhz` objective's `goal`), give the copy its own `id:`, and
run the copy. Other keys: `workload` (a Workload IR document whose precision the PE takes),
`preserve_fmax: true` (the target becomes the incumbent's own measured clock on each stage, so
the answer is how much area can go while the clock stays), `multipliers` / `reducers` /
`pipelines` (narrow the space), `clock_period_ps`, `include_invented`.

## What the model does

Nothing in the first step: a 48-point space is screened exhaustively in minutes and needs a
judge, not a proposer. Every further step (`budget.steps` is 1 + the invention rounds per
pass; the document says 4) asks the model for a **multiplier structure the enumeration does
not contain** -- after the screen, so the prompt carries each built-in's measured worst
path and area from this very run as the number to beat. A proposal is refused before any tool
runs if it is sequential or just the behavioral multiply already in the space; then it faces
Verilator at the sign corners, with compile errors and failing vectors fed back, bounded. Every
multiplier that passes is kept and joins the menu of every later run, where the screen ranks
it against the four built in.
