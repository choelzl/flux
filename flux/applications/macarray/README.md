# macarray/ -- the MAC processing element's microarchitecture, on real ASAP7 numbers

The array is given: `lanes` products summed per cycle at the precision the workload IR
declares (int8 x int8 by default, from `core/ir/workload/examples/mlp-gemm0.yaml`). What is
searched is inside the PE:

| knob | values | what it changes |
|---|---|---|
| multiplier | `behavioral` (the `*` operator), `array` (sign-magnitude shift-and-add), `booth4` (radix-4 Booth), `wallace` (carry-save tree), plus anything a model invented | how each product is formed |
| reducer | `chain`, `tree`, `csa` | how the products (and the accumulator input) become one sum |
| pipeline | 0, 1, 2, 3 | register stages: products; plus the output; plus a cut through the reduction |

48 points (4 x 3 x 4). Every one is generated by code (`lib/src/flux_macarray/rtl.py`), **verified by
Verilator** against golden vectors seeded from the workload with its latency checked against
the number of stages it claims, **screened** by Yosys + OpenSTA (synthesis, no wires: seconds,
optimistic, identical in method), and the finalists spread along the fmax-vs-area frontier are
**placed by OpenROAD** (the number a report may quote). The incumbent is the behavioral
multiply-and-sum every silicon number this repo pinned before was measured on.

```bash
cd flux
nix develop --command flux task check applications/macarray   # tools present? what it will search
nix develop --command flux task run applications/macarray --passes 1 --steps 1   # the screen and placement, no model
nix develop --command flux task run applications/macarray --passes 1 --steps 1 --screen-only   # synthesis only
nix develop --command flux task run applications/macarray   # with invention rounds, until `flux stop`
```

The document says `budget.passes: 0`, so a plain run keeps going until `flux stop` (or `q` in
the TUI); `--passes 1` runs one pass. `--steps 1` is the exhaustive screen alone; each step
above one is an invention round that needs a model (see below). The record and the decided PE
go to `applications/macarray/out/` (`macarray.db`, `macarray.sv`) unless `--db` / `--out` say
otherwise; a resumed run re-measures nothing, because measurements are keyed by the tool
fingerprints and the exact source.

## Changing the ask

There are no per-application flags: the knobs are the document's `params:`. Copy the
folder -- its name is the copy's id, so its record and measurements do not mix with
the original's -- edit the copy, and run it:

```bash
cp -r applications/macarray applications/mac16
# edit applications/mac16/problem.yaml: params.lanes: 16, params.target_mhz: 1500
nix develop --command flux task run applications/mac16 --passes 1
```

| `params:` key | default | what it does |
|---|---|---|
| `target_mhz` | 1000 | the clock the PE must make; the decision is the smallest PE that makes it (also change the `fmax_mhz` objective's `goal`) |
| `lanes` | 8 | products summed per cycle |
| `workload` | null | a Workload IR document; the precision comes from it (default: `core/ir/workload/examples/mlp-gemm0.yaml`, int8 x int8) |
| `preserve_fmax` | false | true: the target becomes the incumbent's own measured clock on each stage, so the answer is how much area can go while the clock stays |
| `clock_period_ps` | null | what the tools are constrained to; default: the target |
| `multipliers`, `reducers`, `pipelines` | all | narrow the space |
| `include_invented` | true | earlier runs' invented multipliers join the menu |
| `problem` | null | what you need, in words, for the model that invents |

The loop's own knobs are the document's `budget:` -- `steps` (1 + the invention rounds per
pass), `repair_attempts`, `finalists` (how many are placed; 0 = the screen only), `workers`,
`passes` -- and the matching `flux task run` flags override them for one run.

The decision is the **smallest PE that makes the target clock** (the interconnect study's
rule). The frontier is printed whole, each row faster than everything smaller and saying what
its extra area bought, so a reader with another clock picks their own point.

## What the model does

Nothing in the first step: a 48-point space is screened exhaustively in minutes and needs a
judge, not a proposer. Each further step of `budget.steps` (4 in the document: three rounds)
asks the model for a **multiplier structure the enumeration does not contain** -- after the screen, so the prompt carries each built-in's measured worst
path and area from this very run as the number to beat -- one combinational module with a fixed interface (`a`, `w` in, `p` out),
refused before any tool runs if it is sequential, uses SystemVerilog casts, or is the
behavioral `a * w` already in the space; then Verilator against the products at the sign
corners, with compile errors and failing vectors fed back up to `repair_attempts` times. Once
a PE makes the clock, the next round asks for a smaller one that still makes it. Every
multiplier that passes is kept under `invented/` and joins the menu of every later run, where
the screen ranks it against the four built in. Without a model these rounds report
themselves skipped and the screen's decision stands.

## Layout

`problem.yaml` is the ask: the statement, `params:`, the objectives, the two stages,
the search (`flow: dse: sweep`) and the budget. `lib/src/flux_macarray/` is the world the
document names (`world: flux_macarray.world:World`): `config` (the space and the shape), `rtl`
(the generator), `verify` (golden vectors and the Verilator verdict), `measure` (the two
stages, cached and parallel), `objective` (fmax, area, the frontier, the decision rule),
`invent` (the model's multiplier prompts), `world` (the hooks the loop calls). A script reads
the run's answer with `flux task run ... --json FILE`. The synthesis stage is `flux_evaluator_openroad.run_synthesis_flow`, usable by
any other study.
