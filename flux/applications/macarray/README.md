# macarray/ -- the MAC processing element's microarchitecture, on real ASAP7 numbers

The array is given: `--lanes` products summed per cycle at the precision the workload IR
declares (int8 x int8 by default, from `core/ir/workload/examples/mlp-gemm0.yaml`). What is
searched is inside the PE:

| knob | values | what it changes |
|---|---|---|
| multiplier | `behavioral` (the `*` operator), `array` (sign-magnitude shift-and-add), `booth4` (radix-4 Booth), `wallace` (carry-save tree), plus anything a model invented | how each product is formed |
| reducer | `chain`, `tree`, `csa` | how the products (and the accumulator input) become one sum |
| pipeline | 0, 1, 2, 3 | register stages: products; plus the output; plus a cut through the reduction |
| mapping | `delay`, `area` | what ABC is told to optimise: the clock period (every number pinned before, D278) or nothing, so area; same RTL, different netlist (D366) |

96 points. Every one is generated by code (`lib/src/flux_macarray/rtl.py`), **verified by
Verilator** against golden vectors seeded from the workload with its latency checked against
the number of stages it claims, **screened** by Yosys + OpenSTA (synthesis, no wires: seconds,
optimistic, identical in method), and the finalists spread along the fmax-vs-area frontier are
**placed by OpenROAD** (the number a report may quote). The incumbent is the behavioral
multiply-and-sum every silicon number this repo pinned before was measured on (D225).

```bash
nix develop .#physical --command python3 applications/macarray/demo.py                       # 1 GHz target
nix develop .#physical --command python3 applications/macarray/demo.py --target-mhz 1500 --lanes 16
nix develop .#physical --command python3 applications/macarray/demo.py --invent 2 --screen-only
nix develop .#physical --command python3 applications/macarray/demo.py --workload my-gemm.yaml
```

The decision is the **smallest PE that makes the target clock** (`--target-mhz`, the
interconnect study's rule); with `--preserve-fmax` the target is the incumbent's own measured
clock on each rung, so the answer is how much area can go while the clock stays (D366); the frontier is printed whole, each row faster than everything
smaller and saying what its extra area bought, so a reader with another clock picks their own
point (D362). `--db` accumulates measurements keyed by the tool fingerprints and the exact
source; a resumed run re-measures nothing.

## What the model does

Nothing, by default: a 96-point space is screened exhaustively in minutes and needs a judge,
not a proposer. `--invent N` asks the local model for N **multiplier structures the enumeration
does not contain** -- after the screen, so the prompt carries each built-in's measured worst
path and area from this very run as the number to beat (D370) -- one combinational module with a fixed interface (`a`, `w` in, `p` out),
refused before any tool runs if it is sequential, uses SystemVerilog casts, or is the
behavioral `a * w` already in the space; then Verilator against the products at the sign
corners, with compile errors and failing vectors fed back, bounded. Every multiplier that passes
is kept under `invented/` and joins the menu of every later run, where the screen ranks it
against the four built in.

## Layout

`lib/src/flux_macarray/`: `config` (the space and the shape), `rtl` (the generator), `verify`
(golden vectors and the Verilator verdict), `measure` (the two rungs, cached and parallel),
`objective` (fmax, area, the frontier, the decision rule), `invent` (the model's multiplier
loop), `flow` (the study). The CHIA node is `flux_chia_nodes.macarray_dse_loop`; the MCP tool
`flux_macarray_dse_loop`. The synthesis rung is `flux_evaluator_openroad.run_synthesis_flow`,
added for this study and usable by any other.
