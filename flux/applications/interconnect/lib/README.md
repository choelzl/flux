# interconnect/ — fabric topologies, their RTL, and the IP catalog

Models for the "N clients, M banks, concurrent access" problem
([decisions.md D261](../../docs/decisions.md)). Five families: `xbar_full`, `xbar_hier` (concentrating),
`xbar_staged` (parallel switches per stage, written either as `{switches, in, out}` or, for the
monolithic case, as `ports` naming the intermediate rank sizes — one family, two spellings,
[D285](../../docs/decisions.md)), `clos` (three-stage C(n, m, r)), `hybrid` (layers borrowed
from different families and chained), and `butterfly` (radix-R networks).
Each reports its blocks, pipeline stages, peak concurrency, expected served-per-cycle, and
inter-stage link bits — the wiring that composed cell area does not include
([D265](../../docs/decisions.md)).

## Three layers, and why they are separate

`topology.py` builds and enumerates the space from `(clients, banks, width)` alone, and carries
the ANALYTIC screen model — cheap enough to rank a thousand candidates. Its error is
characterised rather than assumed ([D266](../../docs/decisions.md)): exact for a direct
crossbar, within ~10% wherever each destination has one path, and 21% low for a Clos at m = n,
whose router load-balances better than the model's assumed random choice. Use it to rank, not
to quote.

`fabric.py` generates the WHOLE fabric as SystemVerilog and measures it. Routing tables are
computed from the real wiring, so a topology in which some client cannot reach some bank is
refused rather than simulated; every valid port per destination is kept, because a fabric whose
router always picks the same one is not the fabric its dimensions describe (a Clos measured
identically for m = 2, 4, 7 and 8 before this). Throughput comes from Verilator under
uniform-random traffic, ~5-8 s per fabric.

`catalog.py` is the referenceable IP list behind `flux_ip_catalog`
([D267](../../docs/decisions.md)), on one rule: an entry is listed only if a generator here can
build it. Entries separate published claims (with sources and scope — Clos's non-blocking
conditions are about circuit switching) from what this repo measured, and name the interface
they fit: OBI natively, AXI4-Stream only with a skid buffer that is not generated here.

RTL is generated by code — an arbitrated K:1 selector with a mask-based round-robin arbiter —
so a fabric DSE runs with no model in the loop. The two evaluators that consume this library
are `evaluators/interconnect_struct` (instant screen) and `evaluators/interconnect_phys` (real
Yosys + OpenROAD on ASAP7, plus the Verilator throughput measurement).

## Not here

Buffered or virtual-channel switches, ring and mesh generators (a mesh is evaluable through the
BookSim/Noxim adapters, whose numbers are not comparable to placed silicon), and routing policy
as a searchable dimension — though it is measurably the largest single lever found: the same
radix-4 butterfly served 8.92 or 13.54 words per cycle depending on route selection alone.
